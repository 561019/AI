# 平台 API 约定

## 1. 传输方式

- 服务间默认使用 HTTPS + JSON，编码为 UTF-8。
- 短任务同步返回；长任务返回 `accepted` 和 `task_id`，进度及最终结果通过回调接口传递。
- 前端通知第一阶段使用 SSE；服务间异步交互第一阶段使用 HTTP Webhook。
- 文件正文、数据集和数字资产不直接嵌入请求，通过标准引用传递。

## 2. 路由与边界

每次调用先访问目标层接口，再由目标层接口根据能力登记解析实际模块。模块地址不得暴露给前端，也不得写死在业务流程中。

层接口按顺序执行：来源校验 → 身份验证 → 幂等检查 → 权限检查 → 能力解析 → 模块调用 → 输出安全检查 → 审计记录 → 返回。

## 3. 标识符

- `message_id`：本次网络消息唯一编号；每次重发仍使用新编号。
- `request_id`：一次请求/回复对的编号。
- `trace_id`：一笔端到端业务链路编号，全链路保持不变。
- `parent_request_id`：子任务指向父请求。
- `task_id`：异步任务编号。
- `idempotency_key`：具有副作用的请求必填；同键同内容返回原结果，同键不同内容返回冲突。

所有标识符使用 UUID 字符串。服务必须原样回传 `trace_id` 和 `request_id`。

## 4. HTTP 与业务状态

- `200`：请求已处理，业务状态可能为 `success` 或可恢复的业务拒绝。
- `202`：任务已受理，业务状态必须为 `accepted`。
- `400`：协议或字段错误。
- `401`：身份未认证。
- `403`：权限拒绝。
- `404`：资源或能力不存在。
- `409`：幂等、版本或状态冲突。
- `422`：业务前置条件不满足。
- `429`：限流。
- `500/502/503/504`：服务异常、依赖异常、不可用或超时。

模块不得使用自然语言文本代替结构化错误码。

## 5. 同步、异步与超时

- 预计 10 秒内稳定完成的任务可以同步执行。
- 超过 10 秒、需要真人确认或依赖外部回调的任务必须异步执行。
- 调用方设置 `deadline_at`；被调用方不得在截止时间后启动新的副作用。
- 只对明确标记 `retryable=true` 的失败进行自动重试。
- 写操作重试必须使用相同 `idempotency_key`。

## 6. 身份与权限

- `actor` 表示当前实际操作真人；智能体放在 `delegation` 中，不替代真人身份。
- 登录、能力调用、数据读取、数据写入、资产调用、外部写入和真人确认分别判权。
- 长任务在关键动作执行前和最终结果返回前重新判权。
- 权限判定只对当前操作有效，不在业务模块中缓存或复制规则。

## 7. 安全与审计

- 外部客户端使用用户访问令牌；服务间使用独立服务身份，不允许沿用用户令牌冒充服务。
- 回调必须使用服务身份，并发送 `X-Callback-Timestamp`、`X-Callback-Nonce`、`X-Callback-Signature`；签名覆盖时间戳、随机数和原始请求体。
- 接收方拒绝超出允许时间窗的签名、重复随机数和不在登记名单中的服务身份。
- API 密钥、模型密钥和外部系统凭据不得出现在请求日志中。
- 审计记录默认保存元数据和引用，不默认保存完整业务正文。
- 敏感内容外发前必须调用安全合规检查。
- 每次权限判定记录 `decision_id` 和 `policy_version`。

## 8. 兼容性

- URL 使用主版本，例如 `/api/v1/...`。
- 新增可选字段属于兼容变更；删除字段、修改含义或改变必填性属于破坏性变更。
- 未识别的可选字段应忽略；未识别的枚举值必须返回明确协议错误，不得猜测执行。
