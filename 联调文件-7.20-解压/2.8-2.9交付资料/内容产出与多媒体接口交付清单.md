# 内容产出与多媒体接口交付清单

编制日期：2026-07-17

## 一、交付范围

本交付包用于验证内容产出引擎、多媒体生成引擎与流程执行引擎之间的基础联调逻辑。包内包含四个本地模块：

| 模块 | 相对目录 | 默认端口 |
|---|---|---|
| 内容产出引擎 v0.2 | `.\engines\content_engine_v0_2` | `8011` |
| 多媒体生成引擎 v1.1 | `.\engines\multimedia_engine_v1_1` | `8013` |
| 本地知识库 v0.1 | `.\engines\local_knowledge_base_v0_1` | `8012` |
| 本地流程执行引擎 | `.\engines\local_flow_execution_engine` | `8020` |

启动方式见 `README_交付说明.md`。

## 二、内容产出引擎接口

### 1. 接收内容产出子任务

```text
POST /api/content-production/subtasks
```

用途：接收流程执行引擎派发的文字类任务，生成文字初稿或文字成果引用。

支持能力：

| capability_id | 说明 |
|---|---|
| `content_marketing_copy` | 营销文案 |
| `content_report_draft` | 报告初稿 |
| `content_article_draft` | 文章初稿 |
| `content_meeting_summary` | 会议纪要/汇报稿 |
| `content_hot_case_reuse` | 爆款复用文字 |
| `content_agronomy_fertilization_plan` | 专家方案初稿 |
| `content_generic_draft` | 通用文字初稿 |

主要输入字段：

```text
trace_id、workflow_instance_id、node_id、task_id、idempotency_key、caller、actor、capability、input、expected_return、policy
```

返回重点：

```text
task_id、status、accepted_receipt、result_refs、audit_ref、callback
```

### 2. 查询内容产出任务

```text
GET /api/content-production/tasks/{content_task_id}
```

用途：查询任务状态、文字结果、结果引用和回调记录。

### 3. 查询内容产出能力

```text
GET /api/content-production/capabilities
```

用途：给流程执行引擎或平台能力登记侧读取当前可承办能力。正式路由仍应以平台能力登记表为准，本接口只说明本模块当前支持什么。

## 三、多媒体生成引擎接口

### 1. 接收多媒体子任务

```text
POST /api/multimedia/subtasks
```

用途：接收流程执行引擎派发的图片、视频、音频类任务，通过本地知识库服务模拟 L1.13 知识库取材，并生成方案、提示词和素材引用。

支持能力：

| capability_id | 说明 |
|---|---|
| `text_to_image` | 文生图/海报方案 |
| `text_to_video` | 文生视频接口位 |
| `video_editing` | 视频剪接方案 |
| `fixed_short_video` | 固定类别短视频方案 |
| `digital_human` | 数字人接口位 |
| `text_to_speech` | 文字转语音方案 |
| `media_processing` | 音画合成与媒体处理方案 |
| `music_sound` | 音乐音效接口位 |
| `multilingual_version` | 多语种翻译版本接口位 |

主要输入字段：

```text
trace_id、workflow_instance_id、node_id、task_id、idempotency_key、caller、actor、capability、input、expected_return、policy、task_type、capability_id、output_type、requirement、use_llm、model_dispatch_interface_slot
```

返回重点：

```text
task_id、status、capability_id、output_type、material_package、references、llm_result、model_dispatch_usage、media_outputs、audit_ref、callback
```

### 2. 查询多媒体任务

```text
GET /api/multimedia/tasks/{task_id}
```

用途：查询知识库取材、方案结果、提示词、引用来源和回调记录。

### 3. 查询多媒体能力

```text
GET /api/multimedia/capabilities
```

用途：读取多媒体“七项 + 预留”能力接口位。正式路由仍应由流程执行引擎或平台接口层根据能力登记表固化，本模块只做能力边界校验和承办。

## 四、callback 对接字段

内容产出和多媒体均支持异步回调：

```text
callback_url
callback_envelope_url
callback_protocol
callback_timeout_seconds
callback_headers
```

状态路径：

```text
accepted -> in_progress -> completed / waiting_human / failed
```

说明：

- `callback_url` 用于本地简化回调。
- `callback_envelope_url` 用于平台标准信封回调。
- 详细字段见 `callback字段说明.md`。

## 五、本地验证接口

本地流程执行引擎：

```text
POST /api/flow/start
POST /api/flow/decide
POST /api/flow/callback
GET  /api/flow/list
GET  /api/v1/capabilities
```

本地知识库：

```text
POST /api/kb/task-materials
GET  /api/health
```

说明：本地知识库接口只用于模拟正式 L1.13 知识库检索/取材能力。正式接入时，应替换为平台或基础模块层提供的知识库服务接口；内容产出和多媒体不直接读取知识库数据库。

## 六、当前边界

本次交付可以验证：

1. 流程执行引擎派发内容产出和多媒体子任务。
2. 两个引擎接收任务、校验能力、执行本地逻辑并返回结果。
3. 多媒体通过本地知识库服务取材。
4. 内容产出和多媒体通过 callback 返回执行状态。

暂不承诺：

1. 真实图片、视频、音频文件生成。
2. 正式大模型调度模块接入。
3. 正式权限、安全审计、数字资产、产物库、规则计算接入。
4. 当前 `artifact_ref`、`downloadable_document_ref` 只是本地占位引用。

## 七、不作为正式联调主接口的接口

以下接口仅用于本地调试、页面演示或健康检查：

```text
POST /api/llm/test
POST /api/integration/run
POST /api/reset
GET  /api/health
```
