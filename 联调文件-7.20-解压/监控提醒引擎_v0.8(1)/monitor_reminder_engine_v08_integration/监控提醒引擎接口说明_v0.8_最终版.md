# 监控提醒引擎接口说明 v0.8 最终版

## 1. 文档状态

- 版本：v0.8-final
- 运行模式：Mock 独立功能验证
- 推荐入口：L2 层内统一消息入口
- 正式状态：待平台联合联调

本文档汇总当前有效接口。阶段性文档仅作为开发历史，不作为最终联调合同。

## 2. 职责边界

监控提醒引擎负责：监控事项登记与状态维护、提醒治理、固定模板组装、按岗送达、确认/升级/恢复事实记录、全过程查询。

监控提醒引擎不负责：业务阈值判断、流程调度、同层引擎直接编排、大模型文案生成、权限事实维护和业务动作代办。

## 3. 统一层内消息入口

### 3.1 接口

```http
POST /api/v1/l2/internal/messages
Content-Type: application/json
```

该接口是 v0.8 推荐入口。本地路径为联调暂定值，正式路径等待平台接口控制模块确认。

### 3.2 必要消息字段

```json
{
  "protocol_version": "1.0",
  "message_id": "msg_xxx",
  "parent_message_id": "",
  "trace_id": "TRACE_xxx",
  "request_id": "REQ_xxx",
  "source": {
    "layer": "L2",
    "service_code": "l2.workflow_execution"
  },
  "target": {
    "layer": "L2",
    "service_code": "l2.monitor_reminder"
  },
  "channel": "l2_internal",
  "route_type": "task.dispatch",
  "action": "monitor.item.register",
  "capability_id": "CAP.MONITOR.ITEM.REGISTER",
  "capability_dictionary_version": "local-final-2026.07.18-v0.8",
  "registry_version": "1.0",
  "actor": {
    "person_id": "WORKFLOW_SYSTEM",
    "tenant_id": "TENANT_DEMO"
  },
  "context": {
    "workflow_instance_id": "WF_xxx",
    "node_id": "NODE_xxx",
    "task_id": "TASK_xxx"
  },
  "idempotency_key": "IDEMP_xxx",
  "deadline_at": "2026-07-18T18:00:00+08:00",
  "payload": {}
}
```

当前准入约束：来源为 `L2 / l2.workflow_execution`，通道为 `l2_internal`，路由类型为 `task.dispatch`。正式准入配置应改为平台可配置项。

### 3.3 标准回复

- `success`：同步办理完成；
- `accepted`：任务已受理，后续由回调或查询获得最终结果；
- `failed`：办理失败，包含错误码和 `retryable`。

公共字段包括：`message_id`、`parent_message_id`、`trace_id`、`request_id`、`task_id`、`reply_type`、`status`、`timestamp`。

## 5. 辅助查询接口

### 健康检查

```http
GET /api/v1/health
```

返回版本、服务状态、数据库状态、幂等、治理、适配层和 Dashboard 接入状态。

### 能力查询

```http
GET /api/v1/capabilities
```

返回引擎边界、能力清单和当前有效端点。

### 监控事项查询

```http
GET /api/v1/monitor-items
GET /api/v1/monitor-items/{item_id}
```

### 全过程查询

```http
GET /api/v1/traces/{trace_id}
```

返回监控事项、提醒、送达、确认、升级、恢复、流程回调和接口审计记录。

### 适配层状态

```http
GET /api/v1/adapters/status
```

返回 L1.7、L1.8、L1.1、L1.9、通知通道和流程回调 Mock 适配器的调用次数、最近动作和证据编号。

### 接口审计

```http
GET /api/v1/audit-records
```

支持按 trace_id 查询，返回权限 decision_id、安全 audit_ref、来源模块、操作人、HTTP 状态和错误信息。

## 7. 业务字段

监控事项主要字段：`item_id`、`object_type`、`object_id`、`rule_id`、`rule_version`、`receiver_role`、`delivery_channel`、`alert_level`、`repeat_interval`、`merge_key`、`merge_window`、`dnd_rule_ref`、`escalation_rule_ref`、`template_id`、`template_version`、`status`。

提醒办理输入主要字段：`item_id`、`event_id`、`reason`、`current_value`、`threshold_value`、`event_time`、`alert_level`。

## 8. 治理顺序

```text
状态检查 → 幂等检查 → 事件去重 → 未销记抑制 → 同类合并
→ 重复间隔 → 免打扰 → 紧急例外 → 固定模板 → 按岗找人
→ 通知送达 → 流程回调 → 记录与审计
```

## 9. 记录约束

`reminder_record`、`delivery_record`、`confirm_record`、`escalation_record`、`recovery_record` 五类业务记录只增不改。当前状态通过事件链推导，原始提醒事实不被确认或恢复操作覆盖。

## 10. 主要错误情况

| HTTP | 场景 | 说明 |
|---:|---|---|
| 400 | 消息信封不合法/来源不合法 | failed，不进入业务办理 |
| 403 | 缺令牌或越权 Legacy 请求 | 权限拒绝并记录 decision_id |
| 409 | 幂等冲突、监控事项暂停等 | failed，业务阻断符合预期 |
| 422 | 通知通道模拟失败 | failed，可重试，不能记为送达成功 |
| 500 | 未处理异常 | failed，记录审计信息 |
