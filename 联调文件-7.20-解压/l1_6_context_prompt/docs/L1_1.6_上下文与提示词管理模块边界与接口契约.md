# L1-1.6 上下文与提示词管理模块边界与接口契约

版本：v0.1  
定位：上下文与提示词处理引擎  
状态：用于从演示系统收敛到可对接模块

## 1. 模块定位

本模块不做通用聊天产品，也不负责账号、项目、权限、文件存储等平台主数据。  
本模块负责定义和执行“上下文如何读取、压缩、交接、检索、引用、注入，以及提示词如何版本化管理”。

一句话定位：

```text
外部平台提供账号、项目、权限、文件和可见范围；
本模块根据这些边界处理上下文与提示词。
```

## 2. 本模块负责

1. 对话框上下文容量判断
2. 80% 提醒、85% 强制收口策略
3. 工作汇报文件生成
4. 工作交接文件生成
5. 项目级传承包升级
6. 项目内控制中心检索策略
7. 账号级总控制中心跨项目检索策略
8. 跨项目引用进入当前项目的规则
9. 普通对话框使用已导入/已引用内容的上下文注入
10. 控制中心对话历史保留
11. 提示词版本、调用追踪、回退策略
12. 上下文处理结果的结构化输出

## 3. 本模块不负责

1. 账号主数据
2. 项目主数据
3. 用户体系
4. 项目成员和角色
5. 真实权限系统
6. 文件真实存储
7. 文件下载授权
8. 项目删除、恢复、归档
9. 组织关系和跨账号授权审批
10. 生产级数据库治理

这些能力由外部平台负责。本模块只消费外部平台传入的边界信息。

## 6. 上下文注入策略

### 6.1 新建普通对话框

读取顺序：

1. 当前项目最新传承包
2. 当前项目最新工作交接文件
3. 当前项目跨项目引用摘要
4. 用户新输入

原则：

```text
传承包提供长期背景；
工作交接文件提供上一轮短期接续；
跨项目引用只作为已确认进入当前项目的补充背景。
```

### 6.2 普通对话框使用已导入内容

触发表达示例：

```text
参考已经导入该项目的内容
参考已引用内容
参考跨项目引用
参考从项目1导入的内容
参考当前项目引用的文件
```

处理规则：

1. 只检索当前 `project_id` 下的跨项目引用。
2. 不在普通对话框中直接跨项目搜索。
3. 将命中的引用摘要注入本轮模型上下文。
4. 回复中返回 `context_used`，标明引用来源。

### 6.3 项目控制中心检索

项目控制中心只能检索当前项目：

1. 对话框
2. 对话消息
3. 工作汇报文件
4. 工作交接文件
5. 项目传承包
6. 已导入当前项目的跨项目引用

如果用户提出跨项目需求，应返回：

```text
跨项目检索请前往账号级总控制中心。
```

### 6.4 账号级总控制中心检索

总控制中心可以在 `visible_project_ids` 范围内跨项目检索：

1. 项目传承包索引
2. 工作汇报索引
3. 工作交接索引
4. 对话框摘要
5. 文件摘要
6. 客户/业务对象索引

总控制中心只负责定位来源和建议引用，不直接替代原项目上下文。

### 6.5 85% 收口

当对话框容量达到 85%：

1. 生成工作汇报文件
2. 生成工作交接文件
3. Project 控制中心升级项目级传承包
4. 旧对话框进入可回查状态
5. 新对话框读取最新传承包和工作交接文件继续

## 7. 三类核心文件边界

### 7.1 工作汇报文件

用途：给 Project 控制中心汇报本轮工作。  
内容：已完成事项、重要结论、产出文件、风险、应写入传承包的事项。

### 7.2 工作交接文件

用途：给下一个普通对话框直接接续。  
内容：未完成事项、下一步动作、必须读取文件、风险和必要背景。

### 7.3 项目传承包

用途：项目长期上下文。  
内容：所有历史对话框的主线、关键结论、文件索引、业务对象、待办和风险。  
维护者：Project 控制中心。

## 8. 跨项目引用规则

跨项目调用分三步：

```text
总控制中心跨项目检索
  -> 用户确认引用到当前项目
  -> 普通对话框或项目控制中心使用当前项目内的引用
```

普通对话框不能直接跨项目搜索。  
项目控制中心不能直接跨项目搜索。  
只有总控制中心可以跨项目检索。

引用进入当前项目后，属于当前项目上下文边界内的可用材料，但仍保留来源信息。

## 9. 提示词清单

### 9.1 work_report_prompt

用途：生成工作汇报文件。  
输入：session 摘要、对话消息、文件引用、决策、风险。  
输出：Markdown 或结构化 JSON。

### 9.2 handoff_file_prompt

用途：生成工作交接文件。  
输入：session 摘要、未完成事项、文件引用、下一步动作。  
输出：严格 JSON 或结构化 Markdown。

### 9.3 sync_package_compress_prompt

用途：升级项目传承包。  
输入：旧传承包、工作汇报、工作交接、文件索引。  
输出：新版传承包。

### 9.4 project_control_center_answer_prompt

用途：项目控制中心只读检索回答。  
输入：当前项目检索结果。  
输出：来源说明、对话框 ID、文件 ID、建议打开路径。

### 9.5 platform_control_center_answer_prompt

用途：总控制中心跨项目检索回答。  
输入：`visible_project_ids` 范围内检索结果。  
输出：来源项目、对话框、文件、引用建议。

### 9.6 cross_project_reference_extract_prompt

用途：把其他项目来源摘取成当前项目可使用的引用摘要。  
输入：来源片段、目标项目、用户意图。  
输出：引用摘要、来源路径、适用范围。

### 9.7 chat_with_imported_context_prompt

用途：普通对话框使用已导入/已引用内容。  
输入：用户任务、当前项目引用摘要、当前会话上下文。  
输出：任务回答和使用来源列表。

## 10. 提示词版本策略

每个提示词至少应记录：

1. prompt_code
2. scope_level
3. scope_id
4. version_no
5. status
6. content
7. variables_schema
8. change_note
9. published_at
10. trace_id

调用时必须记录：

1. 使用哪个提示词版本
2. 输入摘要
3. 输出文本
4. token / cost / latency
5. fallback 原因
6. 质量评分

## 11. 控制中心历史策略

控制中心不是普通任务对话框，但它需要保留问答历史。

项目控制中心历史：

1. 用户检索问题
2. 控制中心回答
3. 命中记录
4. 引用动作

总控制中心历史：

1. 跨项目检索问题
2. 来源结果
3. 引用到项目动作

控制中心历史不直接触发工作汇报、工作交接或传承包生成。  
后续如果控制中心历史过长，可以做内部摘要，但不应作为普通三件套对外展示。

## 12. 验收用例

### 用例 1：普通对话框 85% 收口

给定普通对话框容量达到 85%。  
系统应生成工作汇报文件、工作交接文件和新版项目传承包。

### 用例 2：新对话框继承

新建普通对话框。  
系统应读取最新传承包和上一轮工作交接文件。

### 用例 3：项目控制中心边界

在项目控制中心输入跨项目问题。  
系统应拒绝跨项目检索，并提示前往总控制中心。

### 用例 4：总控制中心跨项目检索

在总控制中心查询同一甲方。  
系统应在 `visible_project_ids` 范围内返回来源项目、对话框和文件。

### 用例 5：跨项目引用进入当前项目

用户在总控制中心点击“引用到当前项目”。  
系统应生成跨项目引用记录，并能在当前项目控制中心检索到。

### 用例 6：普通对话框使用已导入内容

用户在普通对话框输入：

```text
参考已经导入该项目的内容，帮我完成方案。
```

系统应只读取当前项目的跨项目引用，并在回答中返回使用来源。

### 用例 7：控制中心历史保留

用户在项目控制中心或总控制中心提问。  
切换页面后再次打开控制中心，应恢复历史问答。

### 用例 8：项目可见范围由外部系统控制

外部系统传入 `visible_project_ids`。  
总控制中心只能在这些项目范围内统计和检索。

## 13. 当前 Demo 与正式模块的差异

当前 Demo 为了演示，仍包含：

1. 本地前端项目列表
2. SQLite 存储
3. Mock 权限
4. 简化检索
5. 简化文件存储

正式模块对接时，应由外部平台提供：

1. account_id
2. project_id
3. visible_project_ids
4. permission_scope
5. file_refs
6. 用户和项目状态
7. 文件存储与下载链接

本模块只负责在这些输入边界内完成上下文和提示词处理。
