# L1-1.6 上下文与提示词管理接口契约

版本：v0.1  
模块定位：上下文处理与上下文质量管理  
适用对象：外部平台、项目系统、对话系统、文件系统、权限系统

## 1. 接口设计原则

本模块不管理账号、项目、用户、权限和文件真实存储。  
外部平台必须把当前可见范围、项目 ID、会话 ID、文件引用等信息传给本模块。

本模块只负责：

1. 判断上下文容量
2. 生成工作汇报
3. 生成工作交接
4. 升级项目传承包
5. 项目内检索
6. 总控制中心跨项目检索
7. 跨项目引用进入当前项目
8. 普通对话框使用已导入/已引用上下文
9. 记录上下文使用来源

## 2. 通用请求字段

所有写入类接口建议携带：

```json
{
  "account_id": "acc_001",
  "user_id": "u_001",
  "actor_id": "u_001",
  "project_id": "proj_001",
  "visible_project_ids": ["proj_001", "proj_002"],
  "permission_scope": ["proj_001", "proj_002"]
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| account_id | 当前账号，由外部平台提供 |
| user_id / actor_id | 当前操作者 |
| project_id | 当前项目 |
| visible_project_ids | 当前用户在总控制中心可检索的项目范围 |
| permission_scope | 外部权限系统计算后的可访问范围 |

## 2.1 ID 与边界字段说明

本模块不生成也不维护账号、项目、用户主数据。以下 ID 的真实性、删除状态、权限状态都由外部平台负责，本模块只按传入边界处理上下文。

| 字段 | 含义 | 来源 | 本模块如何使用 |
|---|---|---|---|
| account_id | 当前账号 / 数字分身 / 工作空间 ID | 外部账号系统 | 作为最高上下文边界；本模块默认不跨 account 合并上下文 |
| user_id | 当前业务用户 ID | 外部用户系统 | 用于记录操作者身份，可与 actor_id 相同 |
| actor_id | 本次动作执行者 ID | 外部用户系统或调用方 | 写入审计、生成记录、trace；mock 权限也按它判断 |
| project_id | 当前项目 ID | 外部项目系统 | 项目控制中心、普通对话、三件套生成都只在该项目内工作 |
| visible_project_ids | 当前用户在总控制中心可见的项目 ID 列表 | 外部项目系统 + 权限系统 | 总控制中心跨项目检索的白名单；不在列表内的项目不检索 |
| permission_scope | 当前用户可访问范围 | 外部权限系统 | 正式环境用于权限过滤；Demo 中只保留字段契约 |
| session_id | 普通对话框 / 会话 ID | 外部对话系统或本模块 Demo | 容量、消息、工作汇报、工作交接都绑定该会话 |
| source_project_id | 跨项目引用的来源项目 ID | 总控制中心检索结果 | 说明引用来自哪个项目，保留来源 |
| target_project_id | 跨项目引用进入的目标项目 ID | 当前 project_id | 普通对话框只能使用 target_project_id 等于当前项目的引用 |
| source_session_id | 来源对话框 ID | 总控制中心检索结果 | 用于回查原始对话框，可为空 |
| source_record_id | 来源记录 ID | 总控制中心检索结果 | 可指向传承包、工作汇报、工作交接、消息或文件 |
| source_record_type | 来源记录类型 | 总控制中心检索结果 | 用于展示和质量评估，如传承包、工作汇报、工作交接 |
| file_refs | 文件引用列表 | 外部文件系统 | 本模块只保存引用和摘要，不负责真实文件存储 |

### project_id 的核心规则

```text
项目控制中心：只能查当前 project_id。
普通对话框：只能使用当前 project_id 下的传承包、工作交接和已导入引用。
总控制中心：不使用单个 project_id，而使用 visible_project_ids 做跨项目检索。
跨项目引用：路径中的 project_id 就是 target_project_id。
```

### visible_project_ids 的核心规则

```text
visible_project_ids 必须由外部平台传入。
删除、归档、无权限项目不应该出现在 visible_project_ids 中。
本模块不会扫描数据库中所有出现过的 project_id 作为真实项目列表。
```

### source_project_id 与 target_project_id 的区别

```text
source_project_id：内容从哪里来。
target_project_id：内容被引用到哪里。

普通对话框只能使用 target_project_id = 当前 project_id 的引用。
```

## 3. 容量估算接口

### POST /api/context/estimate

用途：估算输入文本或上下文包会占用多少上下文容量。

请求：

```json
{
  "text": "需要估算的内容",
  "file_refs": [],
  "model": "optional"
}
```

响应：

```json
{
  "estimated_units": 120,
  "strategy": "char_based"
}
```

## 4. 普通对话接口

### POST /api/sessions/{session_id}/chat

用途：普通对话框发送消息。  
如果用户提到“参考已导入/已引用内容”，本模块只读取当前项目内的跨项目引用。

路径字段：

| 字段 | 说明 |
|---|---|
| session_id | 当前普通对话框 ID；必须属于当前 project_id |

请求字段：

| 字段 | 说明 |
|---|---|
| actor_id | 当前操作者，用于审计和 trace |
| project_id | 当前会话所属项目；普通对话框只能使用该项目内上下文 |
| message | 用户本轮输入 |
| visible_project_ids | 可选；普通对话框不使用它做跨项目检索，只用于保持统一契约 |

请求：

```json
{
  "actor_id": "u_001",
  "project_id": "proj_001",
  "message": "参考已经导入该项目的内容，帮我写方案",
  "visible_project_ids": ["proj_001", "proj_002"]
}
```

响应：

```json
{
  "reply": "根据已导入内容，可以这样处理...",
  "auto_handoff": false,
  "session": {
    "id": "sess_001",
    "project_id": "proj_001",
    "capacity_ratio": 0.42
  },
  "context_used": [
    {
      "type": "cross_project_reference",
      "id": "xref_001",
      "source_project_id": "proj_002",
      "source_record_id": "sync_008"
    }
  ],
  "trace_id": "trace_001"
}
```

规则：

1. 普通对话框不能跨项目检索。
2. 普通对话框只能使用当前项目已有上下文。
3. 已引用/已导入内容必须来自当前项目的 `cross_project_reference`。
4. 响应必须返回 `context_used`，便于质量追踪。

## 5. 85% 收口接口

### POST /api/sessions/{session_id}/close

用途：对话框达到 85% 后执行收口，生成三件套。

路径字段：

| 字段 | 说明 |
|---|---|
| session_id | 需要收口的普通对话框 ID |

请求字段：

| 字段 | 说明 |
|---|---|
| project_id | session_id 所属项目 |
| capacity_ratio | 当前容量比例，由上下文容量模块或外部对话系统提供 |

请求：

```json
{
  "actor_id": "u_001",
  "project_id": "proj_001",
  "capacity_ratio": 0.86
}
```

响应：

```json
{
  "work_report": {
    "id": "report_001",
    "artifact_file_id": "file_001"
  },
  "handoff_file": {
    "id": "handoff_001",
    "artifact_file_id": "file_002"
  },
  "sync_package": {
    "id": "sync_001",
    "version_no": 5
  },
  "next_action": "create_or_switch_next_session"
}
```

规则：

1. 80% 只提醒。
2. 85% 强制收口。
3. 收口必须生成工作汇报、工作交接和新版传承包。

## 6. 工作汇报接口

### POST /api/sessions/{session_id}/work-report

用途：生成当前对话框工作汇报。

路径字段：

| 字段 | 说明 |
|---|---|
| session_id | 当前对话框 ID |

请求字段：

| 字段 | 说明 |
|---|---|
| project_id | 当前对话框所属项目 |
| file_refs | 本轮产出文件引用，由外部文件系统提供 |

请求：

```json
{
  "actor_id": "u_001",
  "project_id": "proj_001",
  "file_refs": []
}
```

响应：

```json
{
  "id": "report_001",
  "project_id": "proj_001",
  "session_id": "sess_001",
  "content": "工作汇报内容",
  "prompt_ref": {
```

5. 有文件引用或明确说明无文件

### POST /api/projects/{project_id}/control-center/answer

| 字段 | 说明 |
|---|---|
| project_id | 当前项目 ID；项目控制中心不允许查其他项目 |

## 10. 总控制中心接口

### GET /api/platform/control-center/history

用途：账号级总控制中心跨项目历史总览。

查询字段：

| 字段 | 说明 |
|---|---|
| include_project_ids | 外部平台传入的当前用户可见项目白名单 |
| exclude_project_ids | 外部平台传入的排除项目，如已删除、归档、取消授权 |

请求参数：

```text
include_project_ids=proj_001,proj_002
exclude_project_ids=proj_003
```

响应：

```json
{
  "scope": "platform",
  "summary": {
    "project_count": 2,
    "record_count": 120,
    "matched_count": 120
  },
  "records": []
}
```

### POST /api/platform/control-center/answer

用途：在外部平台传入的可见项目范围内跨项目检索。

请求字段：

| 字段 | 说明 |
|---|---|
| question | 用户跨项目检索问题 |
| include_project_ids | 总控制中心允许检索的项目范围 |
| exclude_project_ids | 需要排除的项目范围 |

请求：

```json
{
  "actor_id": "u_001",
  "question": "查找同一甲方在其他项目里的沟通偏好",
  "include_project_ids": ["proj_001", "proj_002"],
  "exclude_project_ids": []
}
```

响应：

```json
{
  "answer": "相关内容主要来自 proj_002 的传承包 v5。",
  "history": {
    "records": [
      {
        "project_id": "proj_002",
        "kind": "传承包",
        "session_id": "sess_020",
        "record_id": "sync_008",
        "content": "摘要..."
      }
    ]
  }
}
```

规则：

1. 只有总控制中心可以跨项目检索。
2. 检索范围必须来自外部平台传入的 `include_project_ids`。
3. 返回来源，不自动导入当前项目。

## 11. 跨项目引用接口

### POST /api/projects/{project_id}/cross-project-references

用途：把总控制中心找到的来源引用到当前项目。

路径字段：

| 字段 | 说明 |
|---|---|
| project_id | 当前项目 ID，也就是 target_project_id |

请求字段：

| 字段 | 说明 |
|---|---|
| source_project_id | 来源项目 ID，表示内容从哪里来 |
| source_session_id | 来源对话框 ID，可为空 |
| source_record_type | 来源记录类型，例如传承包、工作汇报、工作交接、对话消息 |
| source_record_id | 来源记录 ID，用于回查 |
| source_name | 来源名称，用于前端展示 |
| source_excerpt | 来源摘要；普通对话框后续只注入该摘要 |
| note | 用户或系统备注 |

请求：

```json
{
  "actor_id": "u_001",
  "source_project_id": "proj_002",
  "source_session_id": "sess_020",
  "source_record_type": "传承包",
  "source_record_id": "sync_008",
  "source_name": "传承包_v5.md",
  "source_excerpt": "甲方偏好先看预算，沟通要先给结论。",
  "note": "由总控制中心引用到当前项目"
}
```

响应：

```json
{
  "id": "xref_001",
  "target_project_id": "proj_001",
  "source_project_id": "proj_002",
  "source_record_id": "sync_008",
  "source_excerpt": "甲方偏好先看预算，沟通要先给结论。"
}
```

规则：

1. 引用需要用户确认。
2. 引用后才进入当前项目边界。
3. 普通对话框只能使用已经引用到当前项目的内容。

### GET /api/projects/{project_id}/cross-project-references

用途：读取当前项目已经导入/引用的跨项目内容。

路径字段：

| 字段 | 说明 |

## 13. Langfuse Prompt 接入约定

本模块只管理上下文处理类 prompt。

生产环境 prompt 名称建议：

```text
work_report
handoff_file
sync_package_compress
cross_project_reference_extract
chat_with_imported_context
```

本地部署 Langfuse 后，模块只需要配置：

```env
LANGFUSE_BASE_URL=http://localhost:3000
LANGFUSE_PUBLIC_KEY=pk-lf-xxx
LANGFUSE_SECRET_KEY=sk-lf-xxx
```

Prompt 获取规则：

```text
优先读取 Langfuse production prompt
读取失败则 fallback 到本地 active prompt
仍失败则使用代码内置兜底逻辑
```

## 14. 错误码约定

| 状态码 | 场景 |
|---|---|
| 400 | 请求字段缺失或格式错误 |
| 403 | 外部权限系统拒绝或 mock 权限拒绝 |
| 404 | 资源不存在 |
| 423 | 对话框已锁定 |
| 500 | 模块内部错误 |
| 502 | Langfuse 或模型服务不可达 |
