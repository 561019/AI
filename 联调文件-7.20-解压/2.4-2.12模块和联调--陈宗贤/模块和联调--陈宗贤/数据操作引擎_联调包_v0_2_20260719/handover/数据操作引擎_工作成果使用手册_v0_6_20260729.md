# 数据操作引擎：工作成果使用手册

版本：v0.5  
日期：2026-07-29  
适用对象：联调人员、演示人员、后续接手开发人员  

## 1. 模块用途

数据操作引擎是业务和过程数据的受控操作入口。它接收流程执行引擎派发的任务，对数据做收集、整合登记、存、读、查、改、删和追溯；物理存储由 L1.7 数据模块完成。

它不做以下事情：

- 不读自然语言、不选引擎、不组织流程；
- 不做规则计算、统计分析或趋势预测；
- 不直接调用数字资产、文档解析或知识库模块；
- 不决定权限，只按当前真人调用 L1.8、L1.1、L1.9 的适配接口完成核验、判权和安全检查。

## 2. 正式调用链

```text
L4
→ 意图分析引擎
→ 流程执行引擎
→ POST /api/l2/tasks
→ 数据操作引擎
→ L1.7 数据模块
→ flow.callback
→ 流程执行引擎
→ L4
```

只允许流程执行引擎派单。旧 `/api/l4/parse`、`/api/l4/execute`、`/api/l2/requests` 已禁用并返回 `410 LEGACY_ENDPOINT_DISABLED`。

## 4. 核心接口

| 接口 | 方向 | 用途 |
| --- | --- | --- |
| `POST /api/l2/tasks` | 流程执行 → 数据操作 | 唯一正式任务入口 |
| `GET /api/flow/callbacks` | 流程执行 ← 数据操作 | 读取待接收结果回调 |
| `POST /api/flow/callbacks/{callback_id}/ack` | 流程执行 → 数据操作 | 确认已接收回调 |
| `GET /api/tasks/{trace_id}` | 演示/排查 | 查看任务终态和结果 |

支持动作：`data.persist`、`data.read`、`data.search`、`data.collect`、`data.consolidate`、`data.update`、`data.delete`、`data.trace`。其中 `data.search` 可带 `query_spec` 执行业务记录表的过滤、字段选择、分组、计数和排序；比例、环比、归因和预测必须交给其他引擎。第三方确认使用受限业务类型 `runtime_decision_audit`，只保存决定与上游结果引用。

所有任务至少要有：`trace_id`、`request_id`、流程执行来源、当前真人、动作和 `payload`。写入动作还必须提供 `approval_ref` 或 `retention_policy_ref`。

## 5. 最小持久化请求

```json
{
  "protocol_version": "1.0",
  "message_id": "msg-demo-001",
  "trace_id": "trace-demo-001",
  "request_id": "request-demo-001",
  "source_service": "L2.workflow_execution",
  "actor_id": "manager_all",
  "channel": "l2_internal",
  "route_type": "task.dispatch",
  "action_id": "data.persist",
  "capability_id": "CAP.DATA.PERSIST",
  "payload": {
    "business_type": "conversation_context",
    "data_labels": ["project", "conversation"],
    "company_codes": ["TEST-A"],
    "storage_class": "fixed",
    "retention_policy_ref": "project-default-retention-v1",
    "source_ref": "conversation:msg-001",
    "content": {"speaker": "manager_all", "text": "需要留存的业务对话。"}
  }
}
```

成功后从 `flow.callback` 或任务详情取得 `data_ref`。它是后续读取、更新、删除、追溯的唯一业务数据编号；`storage_uri` 只是 L1.7 的仓管位置，不可替代 `data_ref`。

## 6. 文件与知识库专用规则

文件请求可额外使用：

```json
"artifact": {
  "filename": "甘蔗施肥规程.pdf",
  "media_type": "application/pdf",
  "content_base64": "..."
}
```

本地演示限制为 10 MB。成功回执返回文件元数据和 `storage_uri`，不会返回文件 Base64；若请求 `include_artifact_content=true`，会失败并返回 `ARTIFACT_INLINE_CONTENT_FORBIDDEN`。

网页操作方法：进入“业务数据管理”→“收集与固定存档”，在“业务附件”选择 PDF、Word、Excel、文本、代码或常见图片，并在“内容正文 / 文件业务说明”填写该文件的业务说明。选择文件后页面会显示文件名、媒体类型和大小；超过 10 MB 或空文件会在提交前拒绝。提交成功后，结果区展示文件名、大小、SHA-256 和 L1.7 仓管位置，但不展示文件本体。

不要把文件名或 Base64 粘进正文冒充上传；正文是业务说明，真正的文件必须通过附件选择控件成为 `artifact`。如果是普通项目 PDF，可使用一般业务类型；如果是知识库来源 PDF，必须将业务类型改为 `knowledge_source_file`，并同时填写知识库资产编号和知识库实例引用。

知识库文件需要两步保存，不能省略：

1. 保存原始文件：`business_type=knowledge_source_file`，携带 `knowledge_binding`；回调得到 `document.parse`。
2. 文档解析器处理文件后，将文本、章节、表格作为 `business_type=parsed_document` 保存，`source_ref` 指向原始 `data_ref`，同样携带 `knowledge_binding`；回调得到 `asset.knowledge_source.sync`。

必填绑定：

```json
"knowledge_binding": {
  "kb_asset_id": "KB-001",
  "kb_instance_ref": "kb-instance-001"
}
```

流程执行引擎收到第二步回调后，才应派数字资产引擎调用 L1.13 建立文本切片、向量和检索索引。

## 7. 演示顺序

1. 在控制台进入“业务数据管理”。该页明确标注为“流程执行本地模拟派单”，而不是 L4 直写 L1.7。
2. 用“收集与固定存档”执行 `data.collect` 或 `data.persist`，展示 `data_ref`、标签、L1.7 位置和 `flow.callback`。需要演示 PDF 时，选择一个不超过 10 MB 的文件，填写业务说明后提交；展示文件元数据，不尝试在回执中下载或预览原件。
3. 用“按标签检索”执行 `data.search`，选择结果后执行 `data.read`；检索只返回登记元数据。
   - 选择结果后，页面会在更新、删除卡片上方显示“当前操作对象”，包含完整 `data_ref`、业务类型和标签；只有这张卡显示的对象会被读取、更新或删除。
   - 若切换当前真人，系统会自动清空选择；若手动输入 `data_ref`，页面会提示“未核验”，应先执行 `data.read` 或 `data.trace` 再进行修改或删除。
4. 用“更新版本”执行 `data.update`，再用“读取与追溯”执行 `data.trace` 展示资产账、仓管账和变化事件。
5. 用“逻辑删除”执行 `data.delete`，再读取同一编号，展示不可用但可追溯。更新和删除都会弹出目标 `data_ref` 的二次确认，确认前应核对“当前操作对象”卡。
6. 需要演示整合时，先准备至少两个 `data_ref`，用“整合结果登记”执行 `data.consolidate`；它只登记已有整合结果，不做计算。
7. 演示知识源文件保存后的 `document.parse` 回调，以及解析结果保存后的 `asset.knowledge_source.sync` 回调。
8. 演示缺少知识库绑定、请求内联文件内容、访问旧 HTTP 入口均会被拒绝。

## 9. 常见问题与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `SOURCE_NOT_WORKFLOW_EXECUTION` | 不是流程执行引擎派单 | 修正 `source_service` 或标准来源信封 |
| `RETENTION_BASIS_REQUIRED` | 写入无审批或留存规则 | 补 `approval_ref` 或 `retention_policy_ref` |
| `KNOWLEDGE_BINDING_REQUIRED` | 知识源没有目标知识库引用 | 补 `kb_asset_id`、`kb_instance_ref` |
| `ARTIFACT_INLINE_CONTENT_FORBIDDEN` | 试图在回执中读取 Base64 文件 | 改由 L1.7 受控读取接口按 `data_ref` 获取 |
| `ARTIFACT_INVALID` | 文件为空、超过 10 MB 或附件编码无效 | 选择有效且不超过 10 MB 的文件后重新提交 |
| `DATA_ASSET_NOT_AVAILABLE` | 数据不存在或已经逻辑删除 | 用 `data.trace` 核对状态和历史事件 |
| `410 LEGACY_ENDPOINT_DISABLED` | 调用了旧聚合入口 | 改走 `/api/l2/tasks` |

## 12. 结构化查询的新回执应如何使用（v0.5）

当流程执行引擎需要业务答案材料时，派发 `data.search`，并在 `payload.query_spec` 明确写出要什么结果，而不是只说“查一查”。最低格式如下：

```json
{
  "operation": "list_entity",
  "business_object": {"code": "dealer", "name": "经销商"},
  "resource_types": ["extracted_fields"],
  "filters": {"tenant_id": "tenant-demo"},
  "fields": ["dealer_id", "dealer_name"],
  "sort": [{"field": "dealer_id", "direction": "asc"}]
}
```

收到任务终态后，流程执行引擎按 `result_ref` 读取完整结果，并必须按以下优先级使用：

1. 把 `business_result` 交给内容产出或 L4 作为业务答案材料。
2. 把 `evidence` 留给审计、引用展示和结果复核。
3. 只有在受控复核时才使用 `raw_access.query_ref` 或 `sample_preview`；不得把样本替代完整答案。

页面的“业务数据管理 → 案例九”手动按钮已经按这个顺序展示：先看业务对象、摘要、结果数量和表格，再展开“证据与受控原始访问”。

若源数据是文档/表格解析后的单元格字段，使用 `resource_types=["extracted_fields"]`。数据操作引擎按 `parse_job_id + sheet + row` 还原记录行；流程方仍必须明确 `business_object`，因为字段名本身不能可靠代表业务对象。

允许的 `operation`：`list_entity`、`detail_records`、`count_entity`、`group_metric`、`aggregate_metric`、`max_metric`、`min_metric`。`ratio`、`trend`、`root_cause`、`forecast` 不能派给本引擎；它们应转规则计算或分析预测引擎。
# v0.6 联调使用补充（2026-07-29）

标准联调包位置：`C:\Users\chen3\Desktop\实习项目\数据操作引擎联调包\data_operation_engine`。

1. 执行 `powershell -ExecutionPolicy Bypass -File .\start.ps1`，默认监听 `127.0.0.1:8031`。
2. 流程执行引擎向 `POST /api/v1/data-operation/instructions` 发送 `contracts/input.schema.json` 规定的信封；可直接使用 `samples/sample_request.json` 验证 `data.persist`。
3. 成功后保存返回的 `data_ref`；后续读取、更新、逻辑删除、追溯均由流程执行引擎再次派单，不能由页面直调。
4. 查询任务以 `business_result` 为主结果；`evidence` 用于审计追溯，`raw_access` 仅用于受控复核。通过 `status_url` 可按同一 `trace_id` 查询任务与审计链。

本包的 SQLite 仅为 L1.7 本地模拟。交付目标是验证协议、边界和审计链，不是宣称已经连通真实平台数据、权限或安全服务。
