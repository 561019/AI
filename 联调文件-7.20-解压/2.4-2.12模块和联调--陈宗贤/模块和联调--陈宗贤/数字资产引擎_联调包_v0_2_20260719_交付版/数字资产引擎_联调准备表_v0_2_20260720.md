版本：v0.2｜日期：2026-07-20

## 一、我提供给其他模块的能力

1. **资产登记与检索**：登记、修改、草稿删除和查询 Agent、Skill、Knowledge Base 三类数字资产；返回资产编号、标签、版本、生命周期状态及技术登记信息。
2. **Skill 技术证据登记**：登记 Skill 的研发需求、候选/固定实现引用、固定测试结果、主力模型与备用模型评测记录；本模块不生成代码、不执行 Skill。
3. **知识源状态登记**：登记知识库的知识源对象引用，接收文档表格解析引擎的处理回执，保存处理状态、知识引用和索引引用；不保存 Word/PDF 原文、切片正文或向量正文。

## 二、我提供的接口

### 接口 1：数字资产任务统一入口

- 路径：`POST /api/flow/tasks`
- 方法：`POST`
- 输入：仅接受流程执行引擎经 L2 对内通道派发的完整标准任务信封。关键字段包括：`protocol_version`、`message_id`、`trace_id`、`request_id`、`parent_message_id`、`source`、`target`、`channel=l2_internal`、`route_type=task.dispatch`、`action`、`capability_id`、能力字典/登记表版本、`actor.person_id`、`context.workflow_instance_id/node_id/task_id/data_refs`、`idempotency_key`、`deadline_at`、`payload`。
- 输出：标准回执，仅为 `success`、`accepted`、`failed` 三种；包含 `trace_id`、`task_id`、`service_code`、`action`、`result`。重复投递相同幂等键返回原结果并附 `idempotent_replay=true`。
- 错误情况：缺少信封字段（`MISSING_FLOW_ENVELOPE_FIELD`）；非流程执行引擎来源（`BAD_TASK_SOURCE`）；目标/通道错误；服务或动作不在目录中；真人身份不一致；幂等键冲突；知识源回调与原任务的 `trace_id`、`parent_task_id` 或 `artifact_ref` 不匹配。

可联调动作：

| service_code | action | 说明 |
| --- | --- | --- |
| `l2.digital_asset.asset.create` | `asset.create` | 创建 Agent、Skill、Knowledge Base 登记草稿 |
| `l2.digital_asset.asset.query` | `asset.query` | 查询资产登记册 |
| `l2.digital_asset.asset.update` | `asset.update` | 修改登记并产生版本留痕 |
| `l2.digital_asset.asset.delete` | `asset.delete` | 删除符合生命周期规则的草稿 |
| `l2.digital_asset.skill.model_evaluation.register` | `skill.model_evaluation.register` | 登记主备模型评测证据 |
| `l2.digital_asset.skill.development.request` | `skill.development.request` | 登记 Skill 研发需求 |
| `l2.digital_asset.skill.implementation.register` | `skill.implementation.register` | 登记候选/固定实现引用 |
| `l2.digital_asset.knowledge_source.register` | `knowledge_source.register` | 受理知识源登记，等待回调 |
| `l2.digital_asset.knowledge_source.result.register` | `knowledge_source.result.register` | 登记解析、索引回执 |

### 接口 2：知识源处理结果回执（同一统一入口的异步动作）

- 路径：`POST /api/flow/tasks`
- 方法：`POST`
- 输入：`action=knowledge_source.result.register`；必须沿用知识源登记任务的 `trace_id`，并提供 `parent_task_id`、`source_id`、`artifact_ref`、`processing_status`、`parser_task_ref`、`knowledge_ref`、`index_ref` 和 `result_summary`。
- 输出：`success` 回执，返回知识源处理状态和登记后的引用摘要。
- 错误情况：原任务不存在或追踪编号不一致（`KNOWLEDGE_SOURCE_CALLBACK_MISMATCH`）；回执对象引用与原登记不一致（`KNOWLEDGE_SOURCE_ARTIFACT_MISMATCH`）。

## 三、我需要调用哪些模块

1. **流程执行引擎（L2）**
   - 调用目的：唯一任务组织者。数字资产引擎不直接接收 L4 或其他 L2 引擎调用，也不直接调用同层引擎。
   - 需要对方提供：按标准任务信封向 `/api/flow/tasks` 派发任务；长任务回调沿用 `trace_id`、`task_id` 和引用。
   - 当前是否已 Mock：是。本地以任务信封/路由 Mock 表示流程执行。

2. **账号网关与安全合规（L1.8 / L1.9）**
   - 调用目的：按当前操作真人进行身份、权限与合规校验；提供审计关联。
   - 需要对方提供：真人身份核验、动作许可/拒绝回执、审计追踪编号。
   - 当前是否已 Mock：是。当前本地 Mock 仅用于验证调用边界，不能替代真实权限系统。

3. **数据模块（L1.7）**
   - 调用目的：保存 Agent、Skill、Knowledge Base 的登记信息、版本、标签、技术证据和审计留痕。
   - 需要对方提供：按资产唯一编号的登记持久化、版本写入、引用读取与审计存储能力。
   - 当前是否已 Mock：是。当前以 SQLite 演示登记册代替，不能视为真实数据模块。

4. **知识库模块（L1.13）与文档表格解析引擎（L2）**
   - 调用目的：知识库实例创建、知识源对象保存、文档解析/索引；本模块只登记 `artifact_ref` 和回执结果。
   - 需要对方提供：知识库实例引用、对象引用、解析任务回执、知识引用、索引引用。
   - 当前是否已 Mock：是。当前不处理真实 Word/PDF 内容，不写入向量内容。

5. **进化机制（L1.3）或研发系统**
   - 调用目的：Skill 不具备正式实现时，接收研发需求并返回候选实现引用；候选代码不能直接成为可调用正式 Skill。
   - 需要对方提供：`implementation_ref`、候选版本、来源、测试/验收回执。
   - 当前是否已 Mock：是。仅登记研发需求和候选实现引用。

## 四、当前 Mock 的内容

1. L1.7 数据模块：用 SQLite 代替资产登记、版本和审计存储。
2. L1.8 / L1.9：用本地身份与规则适配器代替真实账号网关、权限和安全合规服务。
3. L1.13 / 文档表格解析：只登记 `artifact_ref`、解析状态、`knowledge_ref`、`index_ref`，不解析真实文档。
4. L1.3 进化机制：只登记候选 `implementation_ref`，不生成、审查或部署正式代码。
5. 流程执行引擎：以请求信封模拟派发；不代表已完成其他引擎的真实串联。

## 五、后续联调风险

1. 协议版本风险：现有层间逻辑图存在 v2.5 / v2.6 版本口径差异；联调前需由老师确认最终能力字典与服务登记表版本。
2. 权限风险：数字资产标签不承载权限；若其他模块把标签、资产编号或前端筛选当权限依据，会产生越权问题。
3. 异步回调风险：知识源登记、解析和索引需保持同一 `trace_id` 和原始对象引用，否则回执会被拒绝。
4. Skill 运行风险：研发需求、候选实现、固定实现、测试通过和模型评测是不同状态；未完成验证的 Skill 不得被当作正式能力调用。
5. Mock 替换风险：真实 L1/L2 服务返回字段、鉴权方式和错误码若不同，需要按正式接口文档进行适配，不能依赖控制台兼容接口。
