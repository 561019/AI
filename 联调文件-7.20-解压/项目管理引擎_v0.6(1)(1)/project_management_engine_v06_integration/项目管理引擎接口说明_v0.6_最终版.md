# 项目管理引擎接口说明 v0.6 最终版

## 1. 文档状态

- 版本：v0.6-final
- 运行模式：Mock 独立功能验证
- 推荐入口：L2 层内统一消息入口
- 正式状态：待平台联合联调

本文档汇总当前有效接口。历史阶段文档不作为最终联调合同。

## 2. 职责边界

项目管理引擎负责：项目登记、状态和档位维护、成员名册、收尾归档、封存重新授权及全过程查询。

项目管理引擎不负责：审批流程组织、权限事实维护、物理文件内容管理、项目分析和同层引擎直接编排。

## 3. 统一层内消息入口

### 3.1 接口

```http
POST /api/v1/l2/internal/messages
Content-Type: application/json
```

该接口是 v0.6 推荐入口。本地路径为联调暂定值，正式路径等待平台接口控制模块确认。

### 3.2 必要消息字段

```json
{
  "protocol_version": "1.0",
  "message_id": "MSG_xxx",
  "parent_message_id": null,
  "trace_id": "TRACE_xxx",
  "request_id": "REQ_xxx",
  "source": {
    "layer": "L2",
    "service_code": "l2.interface_control"
  },
  "target": {
    "layer": "L2",
    "service_code": "l2.project_management"
  },
  "channel": "l2_internal",
  "route_type": "deterministic.request",
  "action": "project.register.simple",
  "capability_id": "CAP.PROJECT.REGISTER.SIMPLE",
  "capability_dictionary_version": "2026.07.v06",
  "registry_version": "registry_2026.07.v06",
  "actor": {
    "person_id": "PERSON_001",
    "tenant_id": "tenant_hanhe"
  },
  "context": {},
  "idempotency_key": "IDEMP_xxx",
  "payload": {}
}
```

当前来源矩阵：

- `l2.interface_control`：可使用 `deterministic.request`、`query.request`；
- `l2.workflow_execution`：可使用 `task.dispatch`、`flow.callback`、`query.request`；
- 只有流程执行引擎可以使用 `task.dispatch` 和 `flow.callback`。

### 3.3 标准回复

- `success`：当前动作同步办理完成；
- `accepted`：长任务已受理，返回 `task_id`；
- `failed`：办理失败，返回稳定错误码和 `retryable`。

治理字段包括：权限 `decision_id`、安全审计 `audit_ref`、`trace_id` 和必要的 obligations。

## 5. 主要业务接口

### 项目登记与审批

```http
POST /api/v1/projects/register
POST /api/v1/projects/{project_id}/approval-result
```

### 项目档位转换

```http
POST /api/v1/projects/{project_id}/grade-change-requests
POST /api/v1/projects/{project_id}/grade-change-result
```

### 项目成员名册

```http
POST /api/v1/projects/{project_id}/members
PUT  /api/v1/projects/{project_id}/members/{person_id}
POST /api/v1/projects/{project_id}/members/{person_id}/remove
GET  /api/v1/projects/{project_id}/members
```

### 项目收尾与归档

```http
POST /api/v1/projects/{project_id}/closure
GET  /api/v1/projects/{project_id}/archive-catalog
```

### 封存项目重新授权与查询

```http
POST /api/v1/projects/{project_id}/archive-authorizations
GET  /api/v1/projects/{project_id}/archive-authorizations
GET  /api/v1/projects/{project_id}/authorized-archive-query
```

### 异步任务

```http
POST /api/v1/tasks/{task_id}/progress
POST /api/v1/tasks/{task_id}/final-callback
GET  /api/v1/tasks/{task_id}
```

### 项目查询与治理证据

```http
GET /api/v1/projects
GET /api/v1/projects/{project_id}
GET /api/v1/projects/{project_id}/trace
GET /api/v1/projects/{project_id}/governance
```

## 6. 健康检查

```http
GET /health
```

返回服务版本、运行模式和基础状态。

## 7. 本地便利接口说明

`/api/v1/projects/*` 和 `/api/v1/tasks/*` 用于 Swagger、本地测试和快速联调。

正式平台调用应优先经过统一消息入口及 L2 层接口，不应由 L4 绕过层接口直接调用。

## 8. 核心状态和约束

- 项目档位：`SIMPLE`、`MAJOR`；
- 业务状态：`APPROVAL_PENDING`、`ACTIVE`、`CLOSING`、`ARCHIVED`、`REJECTED`；
- 成员状态：`ACTIVE`、`SUPERSEDED`、`EXITED`；
- 任务状态：`ACCEPTED`、`RUNNING`、`SUCCESS`、`FAILED`、`CANCELLED`；
- 成员变更保留旧版本，不覆盖历史；
- 批量收权与归档均成功后才能进入 `ARCHIVED`；
- 封存查询只返回目录及 `data_ref`、`artifact_ref`、`asset_ref`，不返回正文。

## 9. 主要错误情况

| HTTP | 场景 | 说明 |
|---:|---|---|
| 400 | 信封、版本、字段或档位非法 | failed，不进入业务办理 |
| 403 | 来源、权限、授权动作或范围不允许 | failed，并记录治理证据 |
| 404 | 项目、任务或能力不存在 | failed |
| 408 | deadline 超时 | failed，需重新发起 |
| 409 | 重复消息、幂等冲突、状态冲突或回调冲突 | failed，不重复推进 |
| 422 | 安全合规阻断 | failed，并记录 audit_ref |
| 500 | 未处理异常 | failed，并保留 trace_id |
