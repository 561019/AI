# L2 流程执行引擎联调说明

更新时间：2026-07-20

## 1. 联调目标

验证一条任务从意图确认到结果返回的最小闭环，且不突破 v2.2 三层架构边界：

```text
L4 / 业务应用层
  -> L2 接口控制模块
  -> 意图分析引擎
  -> 已确认结构化命令
  -> 流程执行引擎
  -> L2 对内通道
  -> 已登记承办引擎
  -> 回调 / 流程推进
  -> L4 结果、待办或通知
```

本资料包的架构权威顺序：`架构基线/AI平台架构框架说明_v2_2_20260716.docx`、`架构基线/层间交互逻辑图_v2_6_20260716.html`、`架构基线/v2_2架构冲突解决与落地决议_v0_1_20260716.md`、`架构基线/架构基线与模块接入推进规范_v0_1_20260715.md`。

## 2. L2 可接收的正式交接

流程执行引擎只接收已由意图分析引擎完成理解、并已完成必要确认的结构化命令。建议使用以下字段：

```json
{
  "command_id": "cmd-001",
  "capability_dictionary_version": "2026.07.16",
  "capability_ids": ["CAP.CONTENT.DRAFT.GENERATE"],
  "parameters": {},
  "dependencies": {},
  "risk_level": "normal",
  "requires_user_confirmation": false,
  "user_confirmed": true
}
```

其中 `capability_ids` 由意图分析引擎对能力字典匹配得到；L2 不重新进行语义判断。若 `requires_user_confirmation=true` 而没有 `user_confirmed=true`，L2 必须拒绝启动。

## 3. L2 选派与派发规则

1. L2 对每个 `capability_id` 查询能力字典与本层能力登记。
2. 只有能力字典、能力登记和承办服务均为 `active` 才可选派。
3. L2 将 `capability_id` 映射为 `service_code`、`action`、`schema_version`。
4. 创建实例时冻结能力字典版本、登记版本、服务代码、动作和协议版本；配置后续改派不影响历史实例。
5. `dependencies` 声明输入输出依赖：有依赖的节点串行，无依赖节点可并行。L2 不擅自重排。
6. L2 仅经本层对内通道派发子任务；承办引擎之间不得直接调用。

当前本地演示能力见 `实现参考/flow_execution_openapi.json` 与 `实现参考/engine.py`。真实能力字典和能力登记由平台配置管理侧提供并由 L2 只读加载。

## 4. 最小联调用例

### 用例 A：能力指令 -> 内容承办引擎 -> 回调

- 意图分析引擎交接 `CAP.CONTENT.DRAFT.GENERATE`。
- L2 查询登记得到 `L2.content.generate`、`action=execute`。
- L2 创建节点和子任务，向承办引擎派发冻结元数据。
- 承办引擎按同一 `trace_id` 回传执行状态与结果。
- L2 推进实例为完成，结果经层接口返回 L4。

验收：派发和回调均携带同一 `trace_id`；实例中可查到冻结快照、派发记录和审计事件。

### 用例 B：需确认的能力指令

- 交接命令声明 `requires_user_confirmation=true` 且未确认。
- L2 返回 `intent_confirmation_required`，不得创建可执行实例。
- 意图分析完成确认后再次交接，L2 才可启动。

### 用例 C：能力未启用

- 能力登记为 `planned`、`inactive` 或承办服务不可用。
- L2 返回 `capability_not_active`，不得退化为通用引擎。

## 5. 各方需提供的联调输入

| 对接方 | 必须提供 | L2 输出 / 期望 |
| --- | --- | --- |
| L2 接口控制模块 | 标准信封校验、真实调用人、权限判定结果、对内通道路由 | 合法的 `flow.start`、回调及统一审计标识 |
| 意图分析引擎 | 已确认结构化命令、能力编号、参数、依赖和确认状态 | L2 受理或明确拒绝码 |
| 平台配置管理 / 能力登记 | 能力字典、能力登记、服务启停与版本快照 | L2 只读查表并冻结选择结果 |
| 承办引擎 | 服务端点、`service_code/action/schema_version`、异步回调契约 | 子任务派发、回调去重与状态推进 |
| L4 工作台 | 任务查询、真人待办决定、结果与通知展示 | 回执、进度、待办、最终结果 |
| L1.2 模板管理 | 模板查询、固定版本读取、模板状态 | 固定模板实例的版本锁定与运行 |

## 6. 当前可联调与非联调项

当前可做第一轮契约与最小闭环联调：意图交接、能力选派、派发、回调、真人决定、L1.2 固定模板读取和 L4 状态查询。

下列项目需要平台组件到位后再做生产级联调：真实权限服务、真实能力登记运行期变更确认与回退、跨进程事务状态仓储、通用 outbox/inbox、消息队列、承办引擎超时取消和补偿。
