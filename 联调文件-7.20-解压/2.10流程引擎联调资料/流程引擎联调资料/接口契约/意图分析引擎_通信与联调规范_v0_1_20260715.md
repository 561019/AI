# L2.1 意图分析引擎通信与联调规范

**版本：** v0.3  
**日期：** 2026-07-15  
**所属层级：** L2 业务引擎层  
**配套文件：** 《AI平台架构框架说明 v2.2》《v2.2 架构冲突解决与落地决议 v0.1》《平台层间通信与权限协议 v0.6》。

## 1. 引擎定位

L2.1 意图分析引擎只负责把用户的自然语言请求理解为可被平台处理的任务描述，并提出后续办理路线。它不直接完成业务，不直接读取企业数据，不直接写入旧系统，不决定审批人，也不直接调用其他 L2 引擎。

一句话边界：**意图分析负责“用户想办什么”，L2 接口负责“将任务交给谁”，流程执行引擎负责“实际怎么办”。**

## 2. 完整调用关系

```text
用户在 L4 对话框输入自然语言
  -> L4 接口：认证、身份上下文、L4 请求权限、日志
  -> L2 接口：服务目录、L2 准入、intent.analyze 权限、日志
  -> L2.1 意图分析引擎
  -> L2 接口对内通道：校验任务计划、重新判定下一跳权限、登记转发
  -> 流程执行引擎
  -> L2 接口 -> L4 接口 -> 用户页面
```

意图分析的结果先返回 L2 接口，不直接向内容产出、流程执行或其他引擎发 HTTP 请求、导入对方代码或写对方数据库。

## 3. L4 传给意图分析引擎什么

L4 页面只把用户输入交给 L4 接口；L4 接口和 L2 接口完成校验后，才由 L2 接口将如下标准请求送达 L2.1。

```json
{
  "protocol_version": "1.0",
  "message_id": "msg_l2_001",
  "trace_id": "trace_001",
  "request_id": "req_001",
  "parent_message_id": "msg_l4_001",
  "source": {
    "layer": "L4",
    "service_code": "l4.workbench"
  },
  "target": {
    "layer": "L2",
    "service_code": "l2.intent_analysis"
  },
  "channel": "l4_to_l2",
  "action": "intent.analyze",
  "request_type": "execute",
  "actor": {
    "person_id": "person_001",
    "position_ids": ["position_marketing_manager"],
    "tenant_id": "tenant_hanhe"
  },
  "context": {
    "conversation_id": "conv_001",
    "ui_scene": "workbench_chat",
    "input_language": "zh-CN",
    "authorization": {
      "decision_id": "decision_intent_001",
      "allowed_action": "intent.analyze",
      "obligations": ["audit_required"]
    },
    "data_refs": []
  },
  "idempotency_key": "chat-msg-001-intent",
  "payload": {
    "input_type": "natural_language",
    "text": "请帮我写一份产品海报文案初稿",
    "attachment_refs": [],
    "client_hints": {
      "selected_scene": "marketing"
    }
  }
}
```

### 3.1 输入字段责任

| 字段 | 谁提供 | 意图引擎如何使用 |
| --- | --- | --- |
| `payload.text` | 用户经 L4 提交 | 识别目标、对象、期望结果、约束和不确定项。 |
| `attachment_refs` | L4 仅传附件引用 | 判断是否需要由流程执行引擎派发文档表格解析子任务，不直接读取文件正文。 |
| `actor` | L1.8 经接口控制模块注入 | 仅用于任务上下文和审计；不得由 L2.1 自行提升权限。 |
| `authorization.decision_id` | L1.1 经接口控制模块注入 | 证明本次 `intent.analyze` 已放行；不等于后续动作已放行。 |
| `conversation_id` / `ui_scene` | L4 | 帮助消歧，不得替代用户实际输入。 |
| `data_refs` | L4 或上游模块按授权提供 | 仅识别是否需要使用，不直接扩大读取范围。 |

### 3.2 L4 不得传入的内容

- L1 模型、数据库、旧系统、消息平台的访问密钥。
- 前端自行判断出的“用户已拥有全部权限”结论。
- 未经授权的业务数据全文、其他用户会话内容或内部提示词。
- 硬编码的审批人、外部系统写入命令或对某个 L2 引擎的强制调用。

## 4. 意图分析引擎返回什么

L2.1 返回的是**任务理解结果**。它必须基于风险、动作类型和确定性规则写出 `requires_user_confirmation`；需要确认时，只能形成待确认意图并返回 L4，确认后才能把不可由前端篡改的结构化命令交给流程执行引擎。允许免确认的低风险只读或确定性请求，也必须在命令中明确标记该依据。无论何种情况，L2.1 都不能直接形成执行引擎子任务。

```json
{
  "reply_type": "success",
  "trace_id": "trace_001",
  "in_reply_to": "msg_l2_001",
  "service_code": "l2.intent_analysis",
  "result": {
    "result_type": "data",
    "data": {
      "intent_status": "waiting_user_confirmation",
      "intent_id": "intent_001",
      "user_goal": "生成产品海报文案初稿",
      "task_mode": "single_engine",
      "risk_level": "low",
      "capability_dictionary_version": "2026.07.16",
      "capability_ids": ["CAP.CONTENT.DRAFT.GENERATE"],
      "requires_user_confirmation": true,
      "confirmation_reason": "user_intent_confirmation",
      "requires_fixed_template": false,
      "requires_third_party_confirmation": false,
      "candidate_command": {
        "command_type": "content_draft_generation",
        "risk_level": "low",
        "requires_fixed_template": false,
        "constraints": {}
      },
      "confirmation_question": "我理解为：为产品生成一份供你审核的海报文案初稿，是否确认？",
      "clarification": null,
      "evidence": {
        "input_message_id": "msg_l2_001",
        "rule_or_model_version": "intent-model-v1"
      }
    }
  }
}
```

### 4.1 五种合法结果

| `intent_status` | 意义 | L2 接口下一步 |
| --- | --- | --- |
| `waiting_user_confirmation` | 已形成理解结果，等待发起人确认 | 将待确认意图持久化并返回 L4；不创建流程、不派发执行引擎。 |
| `confirmed` | 发起人已确认理解结果 | 生成结构化命令并交流程执行引擎；不直接向执行引擎派发。 |
| `needs_clarification` | 关键信息缺失或多个路线无法区分 | 原路返回 L4，请用户补充；不调用其他引擎。 |
| `restricted` | 用户目标触及已知禁止或高风险范围 | 返回 L4 说明需走固定流程/人工入口；不自行放行。 |
| `unrecognized` | 无法可靠理解 | 返回 L4 请求改述或转人工；不伪造任务计划。 |

`failed` 只用于引擎故障、报文不合法或依赖不可用；“用户请求不清楚”是正常业务结果，使用 `success + needs_clarification`。确认、否认和过期属于确定性指令，由 `intent.confirm` 按待确认记录处理。

**确认策略冻结：** 数据/文件存改、外部写入、审批、资产创建/开放、对外发布、高风险或多义请求必须确认；只读查询、纯查看、确定性表单和已登记低风险草稿可免确认。该判断只由意图分析依据登记规则写入命令，不能由流程执行或承办引擎事后自行改变。

## 5. 意图分析后的唯一交接方式

### 5.1 确认前：只保存待确认意图

例如“写一份产品海报文案初稿”，调用链为：

```text
L2.1 intent.analyze
  -> L2/L1 接口 -> context.save_pending
  -> accepted 或 success(waiting_user_confirmation)
  -> L4 展示确认问题
```

待确认记录至少包含 `intent_id`、`trace_id`、发起真人、原始输入引用、理解结果、状态和过期时间。`intent.confirm` 必须由同一真人提交，并使用新的动作级权限决策。否认或超时只结束该意图，不产生流程或执行引擎调用。

### 5.2 确认后：只交流程执行引擎

确认成功后，L2.1 通过 L2 对内通道发送 `flow.start`，载荷只包含已确认命令和引用：

```json
{
  "source": {"layer": "L2", "service_code": "l2.intent_analysis"},
  "target": {"layer": "L2", "service_code": "l2.workflow_execution"},
  "channel": "l2_internal",
  "action": "flow.start",
  "request_type": "execute",
  "trace_id": "trace_001",
  "request_id": "req_001",
  "parent_message_id": "msg_l2_001",
  "actor": {"person_id": "person_001"},
  "context": {
    "intent_id": "intent_001",
    "authorization": {
      "decision_id": "decision_content_001",
      "allowed_action": "flow.start"
    }
  },
  "payload": {
    "confirmed_command": {
      "command_type": "content_draft_generation",
      "user_goal": "生成产品海报文案初稿",
      "capability_dictionary_version": "2026.07.16",
      "capability_ids": ["CAP.CONTENT.DRAFT.GENERATE"],
      "requires_user_confirmation": true,
      "constraints": {}
    }
  },
  "idempotency_key": "req_001-task_001"
}
```

注意：`decision_intent_001` 仅证明可分析意图，不能复用为 `content.generate` 的权限。每一个新动作都必须重新获得适用于该动作、资源、时间和数据范围的 `decision_id`。

流程执行引擎收到 `flow.start` 后，才创建流程实例并按节点向执行引擎群派发子任务。`content.generate` 的权限判断在流程执行准备派发时重新执行；意图分析的 `decision_id` 不得复用。

### 5.3 多步骤或审批类任务

例如“发起本月销售提成计提审批”：

```text
L2.1 返回 requires_fixed_template=true 的任务计划
  -> L2 接口对内通道
  -> flow.start（流程执行引擎）
  -> L1.2 template.retrieve（取并锁定固定模板）
  -> L1.1 position.resolve / permission.decide
  -> 自动节点、人工待办、后续节点
```

意图分析只能标记“需要固定模板”和候选模板类别/编号，不得自行编造审批链、指定具体审批人或绕过流程执行引擎启动流程实例。

### 5.4 需要附件解析、数据或知识的任务

| 用户意图 | L2.1 输出的后续任务 | 实际承办方 |
| --- | --- | --- |
| “把这份 Excel 整理成采购计划” | `document.parse`，再由流程执行引擎编排后续步骤 | 文档表格解析，必要时数据归集/规则计算。 |
| “汇总本月销售并预测下月” | `data.aggregate`、`analysis.forecast` | 数据操作、分析预测。 |
| “报销标准是什么” | `knowledge.answer` | 知识库问答，经 L1.13 检索制度依据。 |
| “把发票录入 ERP” | `flow.start`，标记外部写入和真人确认要求 | 流程执行引擎，经 L1.10 写入。 |

这些动作均由流程执行引擎按节点创建 `l2_internal` 子任务；L2.1 不直接访问附件内容、数据源、知识库或 ERP，也不向这些引擎投递请求。

### 5.5 意图分析自身需要 L1 能力时

L2.1 如需模型、上下文或知识辅助理解，也不得直连 L1。它向 L2 接口提交已登记的下层能力请求，由 L2 接口再经 L1 接口调用：

```text
L2.1 -> L2 接口 -> L1 接口 -> L1.6 context.resolve / L1.5 model.generate / L1.13 knowledge.retrieve
```

第一阶段的最简意图分析可使用规则或占位实现，不以接入模型为前置条件；接入模型后仍必须保留任务计划、权限和审计结构。

## 6. 返回给 L4 的结果

L2.1 的内部结果不必直接展示给用户。L2 接口根据后续办理状态向 L4 返回：

| 情形 | L4 收到的回复 | 页面行为 |
| --- | --- | --- |
| 内容草稿已同步完成 | `success`，结果为内容草稿 | 显示草稿、引用和下一步操作。 |
| 已创建流程或长任务 | `accepted`，结果为 `task_receipt` | 显示处理中，提供任务状态入口。 |
| 信息不足 | `success`，结果包含 `needs_clarification` | 显示追问，不发起下一模块调用。 |
| 无权或禁止办理 | `failed`，错误为 `permission_denied` 或规则拒绝码 | 显示明确原因，不泄露策略内部细节。 |
| 模块或下游故障 | `failed`，错误为 `dependency_unavailable` / `timeout` 等 | 显示可重试或联系处理人的说明。 |

## 7. 各方接口责任

| 责任方 | 必须实现 |
| --- | --- |
| L4 组 | `chat.send` 页面、处理中/补问/成功/失败状态；只调用 L4 接口。 |
| 架构组 | L4/L2 接口控制、公共信封校验、服务目录、权限调用、审计和 `l2_internal` 转发。 |
| L2.1 组 | `intent.analyze`/`intent.confirm` 输入输出 Schema、五种意图状态、待确认状态和结构化命令契约测试；不直接调用其他引擎。 |
| 流程执行组 | 接收 L2 接口转发的结构化命令，创建实例并向执行引擎群派发子任务。 |
| 承办 L2 组 | 只接收流程执行引擎派发的标准子任务，返回标准结果或受理回执。 |
| L1.1/L1.8/L1.9 组 | 身份上下文、动作级权限结论、合规义务和审计依据。 |
| 测试组 | 正常理解、补问、禁止/无权、错误路由、重复请求、下游不可用测试。 |

## 8. 联调验收用例

1. “请帮我写一份产品海报文案初稿”经本人确认后形成结构化命令，先调用 `flow.start`，再由流程执行引擎派发 `content.generate`；L2.1 不直接调用内容产出引擎。
2. “发起本月销售提成计提审批”被识别为固定审批流程，后续进入流程执行引擎，而不是直接调用 L1.2 或 ERP。
3. 请求含义不清时，L2.1 返回 `needs_clarification`，没有产生后续引擎调用。
4. `intent.analyze` 和 `flow.start` 被允许但 `content.generate` 被拒绝时，系统在流程派发前停止，内容产出引擎不收到请求。
5. 同一 `idempotency_key` 重复提交时，不重复创建后续任务。
6. 使用同一 `trace_id` 可以查到 L4 请求、L2.1 结果、L2 内部转发、权限 `decision_id` 和承办结果。
