# v2.2 架构冲突解决与落地决议

**版本：** v0.1  
**日期：** 2026-07-16  
**维护方：** 平台架构组  
**适用范围：** 全平台架构、协议、服务登记、配置管理、联调和运行期变更。  
**最高依据：** 《AI平台架构框架说明 v2.2》。  
**效力：** 本决议用于消除 v2.2 与此前架构资料、以及 v2.2 内部表述之间的实施歧义。发生冲突时，本决议优先于此前所有 Markdown 架构文件；后续将并入 v2.2 正文。

## 1. 已冻结的十项决议

| 编号 | 决议 | 实施要求 |
| --- | --- | --- |
| D-01 | 意图确认按风险和确定性分级，不是所有请求一律确认，也不能由承办引擎自行决定。 | 意图分析输出 `requires_user_confirmation`、原因、风险等级；流程执行只接收已满足该字段要求的命令。 |
| D-02 | 能力登记表改派必须通过契约兼容门禁。 | 改派前校验 Schema、权限动作、数据标签、超时、幂等、回调、健康和回退版本。 |
| D-03 | 新引擎“自动发现”仅发现 manifest，不等于准入。 | 研发提交签名服务登记包；契约/权限/安全测试通过后，由平台配置管理账号确认启用。 |
| D-04 | 业务数据 CRUD 与模块运行状态写入分开。 | 业务数据/长期存档由数据操作引擎组织；运行状态/临时结果由状态责任模块经 L1.7 写入。 |
| D-05 | 上下文逻辑所有权与物理存储分开。 | L1.6 管上下文、待确认意图和提示词生命周期；L1.7 提供物理存储；只允许 `context.*` 服务访问。 |
| D-06 | 临时数据必须有完整生命周期。 | 声明类型、`trace_id/task_id`、TTL、最短保留、延期、删除审计与可恢复性；流程未终态前不得清理所需引用。 |
| D-07 | 能力字典与能力登记表必须版本化。 | 命令和流程实例冻结字典/登记/Schema 版本；新版本只进入新流程；弃用能力必须有替代和迁移规则。 |
| D-08 | 十大经营系统在定义前是 `planned`。 | 不得认领能力、登记 active 服务、被流程执行选派或接入生产数据。 |
| D-09 | 权限按动作、资源、范围、状态实时判定。 | 每次动作保留 `decision_id`；跨层校验不能替代 `data.read`、`system.write`、`asset.use` 等具体授权。 |
| D-10 | 数据归集聚合引擎统一更名为数据操作引擎。 | 标准服务改为 `data.read/create/update/delete/aggregate`；旧 `data.aggregate` 仅作为兼容动作，不再作为引擎名称。 |

## 2. D-01：意图确认策略

### 2.1 强制确认

以下请求必须 `requires_user_confirmation=true`：

```text
数据或文件写入、修改、删除、长期存档
外部系统写入、资金、合同、审批、对外发送/发布
创建、修改、删除、共享智能体/技能/知识库
改变资产开放范围、权限、岗位授权
高风险或不可逆动作
意图置信不足、参数缺失、涉及多个合理解释
```

### 2.2 可规则免确认

以下情况可由意图分析按已登记规则输出 `requires_user_confirmation=false`：

```text
只读查询、纯查看、任务状态查询
已提交的确定性表单或按钮指令
低风险且无外部后果的草稿生成
已由流程模板明确且输入完整的低风险执行步骤
```

免确认不等于免权限。流程执行仍对每个动作重新请求权限和安全检查。对外成果、正式文件、数据持久化等后续动作可另设真人确认节点。

### 2.3 结构化命令最小字段

```json
{
  "command_id": "cmd_xxx",
  "capability_dictionary_version": "2026.07.16",
  "capability_ids": ["CAP.CONTENT.DRAFT.GENERATE"],
  "requires_user_confirmation": true,
  "confirmation_reason": "user_intent_or_irreversible_effect",
  "risk_level": "medium",
  "parameters": {},
  "dependencies": []
}
```

## 3. D-02/D-03/D-07：能力配置变更门禁

能力登记表至少必须保存：

```text
capability_id, dictionary_version, service_code, action, schema_version,
allowed_callers, required_permission_action, data_labels,
sync_timeout_seconds, retry_policy, callback_schema_version,
health_status, contract_test_status, security_test_status,
effective_from, rollback_version, owner, change_ticket
```

改派或启用的状态机：

```text
discovered
-> registered
-> contract_verified
-> security_verified
-> pending_confirmation
-> active
-> draining
-> disabled
-> rolled_back
```

- `discovered` 只说明平台发现部署服务，不可接活。
- `active` 必须经配置确认；运行中流程仍锁定原 `service_code + schema_version`。
- 改派失败可回退到 `rollback_version`；没有回退版本不得进行生产改派。
- 能力字典新增、弃用、替换必须保留版本、替代能力编号和生效日期。

## 4. D-04/D-05/D-06：数据与存储裁决

| 数据类别 | 逻辑责任 | 物理执行 | 最小生命周期 |
| --- | --- | --- | --- |
| 业务数据 CRUD、数据资产登记、长期存档 | 数据操作引擎 | L1.7 数据 | 固定存；需存改权限、版本和审计。 |
| 待确认意图、会话上下文、提示词 | L1.6 上下文与提示词 | L1.7 数据 | 可临时或固定；按 `context.*` 管理，禁止底层直连。 |
| 流程实例、节点、子任务 | 流程执行 | L1.7 数据或流程状态库 | 至少保留至流程终态和审计最短保留期届满。 |
| 解析中间结果、模型临时输入输出 | 对应承办引擎 | L1.7 数据/产物库 | 临时存；关联任务未终态不得删。 |
| 内容/多媒体产物 | 产出引擎 | L1.7 数据/产物库 | 草稿可临时；用户确认存档后为固定存。 |
| 外部写入回执 | L1.10 系统接口，流程执行关联 | L1.7 数据 | 至少保留至对账和审计要求完成。 |

所有写入请求必须携带：

```text
storage_class = temporary | fixed
owner_service
trace_id / task_id
retention_policy
delete_after
legal_hold / recovery_policy
data_labels
```

## 5. D-08/D-09：经营系统和权限裁决

- 十大经营系统状态固定为 `planned`，其能力登记表不得出现 `active` 记录。
- 任何接入前必须完成：业务责任、权威数据、服务接口、状态模型、权限动作、审计和失败恢复评审。
- 权限动作统一最少包含：`asset.use`、`asset.share_scope_change`、`data.read`、`data.persist`、`data.update`、`data.delete`、`system.read`、`system.write`、`human.approve`、`artifact.read`、`model.generate`。
- 权限决策对当前真人、动作、资源、范围、状态、用途和时间有效；每次返回独立 `decision_id`。

## 7. 执行顺序

1. 架构组发布能力字典 v1、能力登记表 Schema v1、服务登记包模板。
2. 各模块组认领能力编号，补齐动作、Schema、权限和回调契约。
3. 测试组完成配置改派、版本冻结、重复回调、临时数据清理和权限动作测试。
4. 平台配置管理账号仅在门禁通过后启用服务；十大经营系统保持 `planned`。
5. 架构组按本决议逐步替换旧名称和旧口径，不允许模块选择旧规则实现。
