# 架构基线与模块接入推进规范

**版本：** v0.5  
**日期：** 2026-07-15  
**维护方：** 平台架构组  
**目的：** 消除不同阶段资料的口径冲突，规定各层、各模块接入平台的唯一边界、通信方式和推进流程。

## 2. 当前唯一层级规则

```text
业务应用层（L4）
  -> 业务引擎层（L2）
  -> 基础模块层（L1）
  -> 已有系统与外部设备
```

- 日常业务请求只允许自上而下发起，结果、回执、通知自下而上返回。
- L4 只能调 L2，L2 才能调 L1；L4 直接调 L1 在接口准入和网络部署上均不允许。
- 层内模块/引擎互不直连，统一经本层接口的对内通道。这里的“对内通道”是接口控制、目录校验、权限和审计后的**受控投递**，不是引擎拥有彼此的业务调用权。
- 只有权限检查可机制性直达 L1.1 权限管理，防止权限检查自身循环；该例外仅用于权限决策。
- 创建 agent、技能、知识库等创建类事务同样走 `L4 -> L2 -> L1`，由流程执行引擎交数字资产引擎处理，不存在创建类直达旁路。

## 3. 当前唯一 L2 调度规则

L2 包含两个命令中枢和十一项执行能力：

```text
意图分析引擎
  -> 与发起人确认理解
  -> 输出已确认的结构化命令
  -> 交流程执行引擎

流程执行引擎
  -> 创建/恢复流程实例
  -> 唯一拥有子任务派发权
  -> 向执行引擎群派发、等待回调、推进或暂停

执行引擎群
  文档表格解析、外部系统对接、数据操作、规则计算、分析预测、
  知识库问答、内容产出、多媒体生成、监控提醒、数字资产、项目管理
  -> 只完成派发给自己的子任务并回传
```

L2 对内通道只允许以下三类受控投递：意图分析 -> 流程执行的已确认结构化命令；流程执行 -> 某一执行引擎的已登记子任务；执行引擎/下游 -> 流程执行的回执或回调。接口控制模块不得依据候选任务计划替意图分析引擎向执行引擎派单，也不得把执行引擎的结果转投另一个执行引擎。

意图分析在命令中必须写入 `requires_user_confirmation`、风险等级和能力字典版本；高风险/写入/审批/资产创建或开放/对外发布必须确认，低风险只读或确定性请求可按登记规则免确认。十大经营系统统一为 `planned`，在完成专项边界和接入评审前不得登记 active 能力或被选派。

以下行为一律禁止：

- 意图分析引擎直接调用内容、知识、数据或其他执行引擎。
- 内容、知识、数据等执行引擎相互调用。
- 监控提醒引擎自行改变业务流程状态。
- 执行引擎直接向 L4 推送业务结果，绕过流程执行和 L4 接口。

## 4. 两类用户交互及其认领规则

| 用户动作 | L2 接收后交给谁 | 原因 |
| --- | --- | --- |
| 新的自然语言请求 | 意图分析引擎 | 需要理解、补问或与发起人确认。 |
| 对意图理解的确认/否认/补充 | 意图分析引擎 | 由 `trace_id` 和待确认意图记录认领。 |
| 流程中真人审批、驳回、补件、继续 | 流程执行引擎 | 由 `trace_id` 和流程/待办编号认领。 |
| L4 表单、按钮等确定性指令 | 按服务目录和追踪编号认领给流程执行或既定承办入口 | 指令已无歧义，不再调用意图分析。 |
| 下游子任务、旧系统、模型的回调 | 流程执行引擎 | 只有它可修改节点和流程状态。 |

## 5. 所有模块必须遵守的推进闭环

```text
标准请求
-> 层接口格式/准入/权限/审计
-> 目标服务受理
-> success / accepted / failed
-> accepted 时持久化任务和状态
-> 合法回调或真人决定
-> 流程执行引擎推进下一步
-> 通知和结果经 L4 送达
```

- `success`：当前动作即时办结。
- `accepted`：已登记长任务，必须带 `task_id`、查询动作和状态。
- `failed`：拒绝或失败，必须带稳定错误码和可重试标识。
- 每个新动作重新请求 L1.1 权限决策；前一步放行不能跨动作复用。
- 每次派发、回调、确认都使用 `trace_id`、父消息编号和幂等键；重复消息不重复推进。

## 6. 模块接入的五道门

1. **边界评审：** 模块负责人提交“负责什么、不负责什么、允许调用谁、禁止调用谁”。
2. **服务登记：** 注册 `service_code`、`action`、调用方白名单、输入/输出 Schema、超时、幂等、健康检查。
3. **权限映射：** 对每个动作声明真人、资源、动作、时间/状态、制度依据和安全义务。
4. **契约测试：** 验证请求、`success/accepted/failed`、权限放行/拒绝、重复调用、超时和回调。
5. **链路验收：** 用同一 `trace_id` 查到每一跳、权限 `decision_id`、状态迁移、审计和 L4 可见结果。

任一门未通过，模块只能保持 `draft`/`mock` 状态，不得接入生产数据、旧系统写入或正式工作台。

## 7. 架构组的持续工作

- 维护本基线、通信协议、服务目录和公共 SDK；其他组不得复制修改公共协议。
- 维护层接口、Mock、契约测试、链路看板、错误码和协议版本。
- 评审模块是否越层、直连、共享数据库、绕过权限或缺少状态持久化。
- 对出现的边界争议给出书面裁决，并更新本基线及受影响模块规范。
- 每次架构变更记录“变更原因、受影响模块、兼容方案、迁移日期、验收人”。
