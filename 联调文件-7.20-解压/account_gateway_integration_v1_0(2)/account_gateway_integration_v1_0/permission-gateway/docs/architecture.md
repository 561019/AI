# 权限模块边界

权限模块是权限事实、实时计算和决策留痕的唯一来源。账号网关继续负责登录、JWT、账号、凭证、数字员工身份和 breakglass 状态。

账号创建时已经实名，因此真人不是独立于账号的第二个身份对象。权限模块统一使用 `user_id = actor_id = person_id`；`persons` 仅镜像账号状态、租户和展示信息，主键直接使用账号 `user_id`。表名和字段名中的 `person` 是权限业务语义，不产生新的编号。

权限不是完整矩阵，而是每次根据岗位标准配置、管理树、数据转授、制度规则以及数据自身约束实时计算。任何业务模块不得复制规则或在权限服务异常时自行放行。

兼容期内账号网关保留 `/auth/validate`，通过 `local`、`shadow`、`remote` 三种模式完成迁移。`remote` 模式失败时必须拒绝，不允许回退到本地旧引擎。

网关调用权限服务时，`actor_id` 和可选 `person_id` 都取 JWT `user_id`，忽略历史请求头中与 JWT 不一致的真人编号。历史 local 数据只用于影子比对，导入时统一归并到账号 ID。

平台其他模块不直接拥有权限逻辑。L1 的流程、模型、上下文、数据、安全、设备、人机、成本和 Agent 模块，以及 L2 的十类业务引擎和 L4 业务界面，统一通过 `source_service + target_service` 调用固定检查接口；资源和数据事实通过账号网关代理的聚合管理接口进入权限模块。见 `docs/platform-integration.md`。
