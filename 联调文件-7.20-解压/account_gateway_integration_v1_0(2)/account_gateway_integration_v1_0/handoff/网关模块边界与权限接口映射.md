# 网关模块边界与权限接口映射

更新日期：2026-07-15

配套结构图：`网关与权限模块结构图.html`。完整逐接口清单：`tables/api_catalog.csv`。

## 1. 结论

账号网关是认证入口和兼容适配层，独立权限模块是权限事实、规则计算和权限决策审计的唯一权威来源。账号创建时已经实名，跨模块统一使用：

```text
JWT user_id = actor_id = person_id
```

网关不得在 `remote` 模式下使用本地 Casbin、组织表或历史策略兜底放行；权限服务不得签发登录 JWT、管理凭证、创建数字员工或改变 breakglass 状态。

## 2. 模块所有权

| 模块 | 拥有并负责 | 不负责 |
|---|---|---|
| Casdoor / 账号源 | 实名账号、登录、OIDC、账号状态和基础角色来源 | 业务权限计算和权限审计 |
| 账号网关 | OIDC 回调、JWT 签发与校验、账号生命周期、凭证、数字员工身份、breakglass、兼容 `/auth/validate`、管理接口认证代理、网关通用审计 | remote 权限事实存储、岗位权限计算、权限服务故障时本地放行 |
| 权限模块 | 实名账号档案镜像、部门、岗位、任职、管理树、岗位标配、转授、制度规则、服务调用规则、数据登记、实时决策和 `permission_decisions` | 登录、JWT 签发、账号凭证、数字员工 token、breakglass 状态 |
| 业务/数据模块 | 资源真实存在性、业务执行、数据内容、动作执行结果 | 自行复制权限规则或绕过权限检查 |

完整机器可读清单见 `tables/gateway_module_boundaries.csv`。

### 2.1 数据所有权和写入边界

| 数据类别 | 唯一权威模块 | 权威存储 | 其它模块的处理方式 |
|---|---|---|---|
| 实名账号、登录身份 | Casdoor / 账号源 | Casdoor users | 网关读取并签发平台 JWT；权限模块只保留档案镜像 |
| JWT、凭证、数字员工、breakglass、租户、审批 | 账号网关 | 网关 SQLite / Casdoor | 权限模块不得创建、修改或复制这些状态 |
| 部门、岗位、任职、管理树 | 权限模块 | 权限 SQLite | `shadow/remote` 由网关认证后代理写入，禁止双写网关 local 表 |
| 岗位标配、转授、制度、服务调用规则 | 权限模块 | 权限 SQLite | 业务模块不得缓存为本地放行规则 |
| 数据登记、动作目录、资源目录 | 权限模块中的权限事实 | 权限 SQLite | 数据内容仍归业务/数据平台；权限模块只保存授权所需元数据 |
| 权限决策审计 | 权限模块 | `permission_decisions` | 追加写；网关通用审计不能替代权限决策审计 |
| 登录、账号操作和代理调用审计 | 账号网关 | `audit_logs` | 与权限审计通过 `trace_id/request_id` 关联 |
| 真实业务内容和动作执行结果 | 业务/数据模块 | 对应业务数据库 | 获得 `allow=true` 后由业务模块执行，网关和权限模块不代执行 |

## 3. 对外接口边界

### 3.1 业务运行期校验

旧调用方继续调用网关：

```http
POST http://127.0.0.1:8080/auth/validate
Authorization: Bearer <JWT>
```

网关先执行 JWT、数字员工、breakglass 和租户前置检查，再把旧请求头转换为：

```http
POST http://127.0.0.1:8001/api/permission/check
Content-Type: application/json
```

`remote` 模式的权限结果只来自权限模块。权限服务返回允许时，网关将 `decision_id` 暴露为兼容响应中的 `policy_id`；正常拒绝返回 HTTP 200、`allow=false`；依赖错误返回 HTTP 503、`allow=false`。

### 3.2 组织和权限管理接口

联调方只连接网关的四个聚合入口：

| 方法 | 网关路径 | 权限模块同路径 | 用途 |
|---|---|---|---|
| POST | `/api/org/commands` | `/api/org/commands` | 岗位、任职、域和上级关系写入 |
| GET | `/api/org/snapshot` | `/api/org/snapshot` | 组织岗位快照和管理树查询 |
| POST | `/api/permissions/commands` | `/api/permissions/commands` | 岗位标配、转授、资源和数据登记 |
| GET | `/api/permissions/snapshot` | `/api/permissions/snapshot` | 权限事实和访问来源对账 |

在 `shadow/remote` 模式下，网关完成 JWT 校验后删除外发的 `Authorization`，只向权限模块传递：

```http
X-Actor-ID: <JWT user_id>
X-Actor-Roles: <JWT role_list，以逗号连接>
X-Tenant-ID: <JWT org_id>
```

请求方法、路径、query 和 JSON body 原样代理。权限模块再次执行角色、租户、引用对象和业务规则校验。

### 3.3 接口归属总表

| 模块 | 接口组 | 认证/调用方 | 主要传输内容 | 边界说明 |
|---|---|---|---|---|
| 账号网关 | `GET /health`、`GET /login`、`GET /callback` | 健康检查 / OIDC | OIDC code、state、平台 JWT | 认证入口，只归网关 |
| 账号网关 | `/api/accounts*` | Bearer JWT；本人或管理员 | 账号资料、生命周期、冻结和交接 | 账号权威操作；不写权限规则 |
| 账号网关 | `/api/credentials*` | Bearer JWT；owner/admin | 加密凭证元数据和使用请求 | 凭证明文不得进入权限模块 |
| 账号网关 | `/api/digital-employees*` | Bearer JWT；owner/admin | 数字员工身份、token、执行模式 | 数字员工身份归网关；不得拥有真人数据权限 |
| 账号网关 | `/api/breakglass*` | Bearer JWT；admin | 启停、审批、有效期、复盘 | 应急状态归网关；权限模块只接收已验证上下文 |
| 账号网关 | `/api/tenants*`、`/api/approvals*`、`/api/approval-templates` | Bearer JWT | 租户成员和审批状态 | 网关业务控制面 |
| 账号网关 | `/api/audit/*` | Bearer JWT；admin/security | 通用操作审计、导出、安全事件 | 不等同于权限决策审计 |
| 账号网关 | `/api/ui-permissions`、`/api/integrations/{provider}/*` | Bearer JWT | UI 面板、HR/钉钉/企微同步状态 | 展示和同步入口 |
| 账号网关 | `POST /auth/validate` | Bearer JWT；旧调用方 | 旧请求头、资源、动作、owner、trace | 兼容入口；`remote` 转为权限 JSON |
| 账号网关 | `/api/org/*`、`/api/permissions/*` | Bearer JWT；IM/DSM/admin | `action + payload` 或 query | `shadow/remote` 只做认证代理，不保存权限事实 |
| 权限模块 | `POST /api/permission/check` | 可信内网服务 / 网关 | `actor + action + data + context` | 唯一运行期权限决策入口 |
| 权限模块 | `GET /api/permission/audits` | 审计、安全、排错方 | trace、actor、result、时间和分页 | 权限决策审计查询 |
| 权限模块 | `/api/org/commands|snapshot` | 网关注入可信头 | 人员档案、部门、岗位、任职和管理树 | 组织权限事实权威接口 |
| 权限模块 | `/api/permissions/commands|snapshot` | 网关注入可信头 | 标配、转授、制度、服务规则、数据和资源 | 权限配置事实权威接口 |
| 权限模块 | `GET /api/integrations/capabilities` | 平台模块 | 版本、通道、模块 ID 和启用状态 | L1/L2/L4 接入能力发现 |
| 权限模块 | `POST /api/integrations/events` | 未来可信服务身份 | 标准事件包络 | v1 固定返回 501，不写权限库 |

## 4. `/auth/validate` 字段映射

核心映射如下，完整表见 `tables/gateway_permission_field_mapping.csv`。

| 权限字段 | 网关来源 | 规则 |
|---|---|---|
| `trace_id` | `X-Trace-ID` | 缺失时生成 `trace_gateway_*` |
| `request_id` | `X-Request-ID` | 缺失时生成 `request_gateway_*` |
| `actor_id` | JWT `user_id` | 必填；不信任客户端主体头 |
| `person_id` | JWT `user_id` | 固定等于 `actor_id`，忽略历史独立真人编号 |
| `action` | `X-Action` | 必填 |
| `source_service` | `X-Source-Service` | 默认 `account_gateway` |
| `target_service` | `X-Target-Service` | 默认 `legacy_runtime` |
| `data_label` | `X-Data-Label` | 默认 `normal` |
| `data_state` | `X-Data-State` | 默认 `active` |
| `tenant_id` | `X-Tenant-ID` 或 JWT `org_id` | 未传时使用 JWT 租户；普通 token 不得跨租户 |
| `position_id` | `X-Position-ID` | 可选 |
| `resource_type` | `X-Resource-Type` | 必填；固定枚举 |
| `resource_id` | `X-Resource-ID` | 缺失时仅作旧接口占位兼容 |
| `domain_id` | `X-Domain-ID` | 可选 |

## 5. 模式和故障语义

| 模式 | `/auth/validate` 决策 | 聚合管理接口 | 权限服务故障 |
|---|---|---|---|
| `local` | 网关旧引擎 | 网关 local Store | 保持旧行为 |
| `shadow` | 返回旧引擎结果，同时记录新旧差异 | 写入和读取权限模块 | 不改变本次旧结果，必须记录差异 |
| `remote` | 仅权限模块 | 代理到权限模块 | HTTP 503，`allow=false`，禁止本地回退 |

生产切换顺序固定为 `local -> shadow -> remote`。只有可解释差异全部清零后才能进入 `remote`。

## 7. 联调方必须遵守

1. 业务请求只信任 JWT 主体，`X-User-ID`、`X-Person-ID` 不能覆盖 JWT `user_id`。
2. 每次业务访问都执行运行期检查，快照只能对账，不能替代检查。
3. 同一调用链复用 `trace_id`，每个请求使用唯一 `request_id`。
4. 调用方同时判断 HTTP 状态和 `allow`，不能把 HTTP 200 等同于允许。
5. `remote` 返回 503 时停止业务操作，不得自行放行或调用 local 权限副本。
6. 组织和权限事实只写权限模块，网关不得双写。
