# 账号、岗位和权限对应关系

## 核心关系

```text
Casdoor 实名账号 / JWT user_id
        │ 同一 ID：user_id = actor_id = person_id
        ▼
persons.id（实名账号档案镜像，不是第二套真人）
        │ 1:N
        ▼
person_position_assignments.position_id
        │ N:1
        ▼
positions.id
        │ 1:N
        ├── position_standard_permissions      岗位标准配置
        ├── person_manager_edges               管理树可见范围
        ├── data_delegations                   真人间数据转授
        ├── data_registry                      owner/初始参与人权限
        └── institution_policies               制度允许或强制拒绝
```

权限不是一张静态“账号权限结果表”。每次请求都按账号、当前有效任职、数据自身约束和上述权限来源实时计算，并把结果写入 `permission_decisions`。

## 标识定义

| 标识 | 示例 | 来源 | 说明 |
|---|---|---|---|
| `user_id` / `actor_id` / `person_id` | `user_fu` | Casdoor/JWT | 同一个实名账号和实际操作人，三个字段值必须相同 |
| `position_id` | `huazhong_sales` | HR/IM | 岗位席位；一人可多岗 |
| `department_id` | `dept_sales_huazhong` | HR/IM | 岗位所属部门 |
| `domain_id` | `domain_huazhong` | DSM | 唯一直属上级和管理树所在域 |
| `resource_id` | `sales_opportunities` | 业务/数据平台 | 数据或资源唯一编号 |
| `policy_id` | `position_standard:123` | 权限引擎 | 本次允许命中的规则来源 |

## 角色与岗位不能混用

JWT `role_list` 主要控制网关管理接口和 UI，例如 `hanhe_im`、`hanhe_dsm`、`hanhe_admin`。岗位 `position_id` 决定业务标准配置。`hanhe_admin` 不是可以查看所有业务数据的超级用户；业务数据仍需运行期权限检查。

## 权限来源与优先级

| 顺序 | 来源 | 表 | 命中示例 |
|---:|---|---|---|
| 1 | 服务调用关系 | `service_call_rules` | `intent_engine -> content_engine` |
| 2 | 数据自身动作、标签和状态 | `data_actions`、`data_registry` | frozen 数据拒绝读取 |
| 3 | 制度强制拒绝 | `institution_policies(effect=deny)` | 高风险动作禁止 |
| 4 | 数据 owner / 初始参与人 | `data_registry` | `data_owner:*`、`data_initial:*` |
| 5 | 岗位标准配置 | `position_standard_permissions` | `position_standard:*` |
| 6 | 管理树 | `person_manager_edges` | `manager_scope:*` |
| 7 | 个性化转授 | `data_delegations` | `delegation:*` |
| 8 | 制度允许 | `institution_policies(effect=allow)` | `institution_policy:*` |
| 9 | 无匹配 | 无 | 默认拒绝 |

制度拒绝优先于所有允许来源。权限过期、真人无有效岗位、数据非 active 或权限服务异常都不能放行。

## local 与 remote 表名对照

| 业务概念 | 网关 local 兼容表 | 权限服务权威表 |
|---|---|---|
| 实名账号 | 挂岗表内历史 `person_id/user_id` 字段 | `persons`，其中 `id=actor_id=Casdoor user_id` |
| 岗位 | `positions` | `positions` |
| 任职 | `person_position_assignments.user_id` | `person_position_assignments.actor_id` |
| 岗位标配 | `position_standard_resources` | `position_standard_permissions` |
| 上下级 | `person_manager_edges` | `person_manager_edges` |
| 数据转授 | `delegations` | `data_delegations` |
| 数据登记 | `data_records` | `data_registry` |
| 审批临时策略 | `runtime_policies` | 导入为 `institution_policies` |
| 权限审计 | `audit_logs` 中 `auth.validate` | `permission_decisions` |

切到 `shadow/remote` 后，权限服务表是唯一权威来源，不得继续直接写网关 local 权限表。旧 local 表允许双字段只是兼容历史数据；所有新写入必须使用同一个账号 ID，导入工具会把历史 `person_id` 归并为 `user_id`。

权限服务旧库执行 Alembic `0002_account_person_identity` 时，会同步归并挂岗、上下级、转授、owner、初始参与人和历史决策引用，然后安装数据库写入保护。升级前需备份数据库，冲突数据必须先治理后再迁移。
