# 联调接口说明

网关和权限模块的所有权边界、接口归属和完整字段转换见 `网关模块边界与权限接口映射.md`；结构总图见 `网关与权限模块结构图.html`；测试过程见 `网关权限联调测试可视化.html`。

## 1. 服务地址

| 服务 | 编码 | 默认地址 | 健康检查 |
|---|---|---|---|
| 账号网关 | `account_gateway` | `http://127.0.0.1:8080` | `GET /health` |
| 权限服务 | `permission_gateway` | `http://127.0.0.1:8001` | `GET /health` |
| Casdoor | `casdoor` | `http://127.0.0.1:8000` | Casdoor 自带健康接口 |

除健康检查、登录回调和固定权限检查外，网关业务接口均使用：

```http
Authorization: Bearer <JWT>
Content-Type: application/json; charset=utf-8
```

JWT 至少包含 `user_id`、`org_id`、`role_list` 和 `exp`。账号创建时已经实名，因此 `user_id` 同时是真人唯一编号；接口中的 `actor_id`、`person_id` 必须与它相同，不能再生成另一套真人 ID。

## 2. 组织命令

`POST /api/org/commands`

```json
{
  "action": "create_position",
  "payload": {
    "id": "position_sales_001",
    "title": "销售专员",
    "department_id": "dept_sales",
    "tags": ["sales"]
  }
}
```

支持命令：

| action | 关键字段 | 调用角色 |
|---|---|---|
| `create_position` | `id,title,department_id,tags` | `hanhe_im` / `hanhe_admin` |
| `assign_person_position` | `user_id,position_id`；兼容字段 `person_id` 必须等于 `user_id` | `hanhe_im` / `hanhe_admin` |
| `end_person_position` | `id` | `hanhe_im` / `hanhe_admin` |
| `create_domain` | `id,name,dsm_user_id` | `hanhe_admin` |
| `upsert_manager_edge` | `person_id,manager_person_id,domain_id` | `hanhe_dsm` / `hanhe_admin` |

写入 payload 未提供 `tenant_id` 时使用 JWT `org_id`。同一实名账号可以担任多个岗位，但同一岗位席位同一时刻只能有一个 active 任职。

## 3. 组织快照

`GET /api/org/snapshot?manager_person_id=<id>&domain_id=<id>`

返回 `positions`、`assignments`、`domains`、`manager_edges` 和递归 `subordinates`。不传 query 时返回当前 JWT 租户快照。

## 4. 权限命令

`POST /api/permissions/commands`

岗位标准权限示例：

```json
{
  "action": "create_position_standard_resource",
  "payload": {
    "position_id": "position_sales_001",
    "resource_type": "data",
    "resource_id": "sales_opportunities",
    "action": "fetch",
    "owner_user_id": "data_owner_001"
  }
}
```

常用命令：

| action | 用途 |
|---|---|
| `create_position_standard_resource` | 配置岗位标准权限 |
| `create_delegation` | 创建真人间数据转授 |
| `create_resource` | 登记工具、技能、知识库或数字员工资源 |
| `register_data` | 登记数据及其 owner、状态、允许动作和初始参与人 |
| `register_data_action` | 登记合法数据动作 |
| `set_data_status` | 冻结、禁用或恢复数据状态 |
| `request_resource_publication` | 申请资源升层发布 |
| `approve_resource_publication` | 批准资源发布 |

## 5. 权限快照

`GET /api/permissions/snapshot?resource_id=<id>&person_id=<id>`

返回岗位标准权限、转授、资源、数据动作、数据登记、`data_access_summary` 和发布申请。快照用于对账，不替代运行期检查。

## 6. 旧网关运行期校验

`POST /auth/validate`

必填请求头：

| 请求头 | 含义 |
|---|---|
| `Authorization` | Bearer JWT |
| `X-User-ID` | 当前操作账号，必须与 JWT 真人身份一致 |
| `X-Resource-Type` | `tool/data/skill/knowledge/digital_employee` |
| `X-Resource-Owner-ID` | 资源归属账号 |
| `X-Action` | 本次动作 |

建议同时提供：`X-Request-ID`、`X-Trace-ID`、`X-Resource-ID`、`X-Tenant-ID`、`X-Person-ID`、`X-Position-ID`、`X-Domain-ID`、`X-Resource-Owner-Person-ID`。

允许：

```json
{"allow": true, "policy_id": "position_standard:123"}
```

拒绝：

```json
{"allow": false, "reason": "action_not_granted"}
```

业务拒绝通常返回 HTTP 200；认证、字段或依赖错误使用 4xx/5xx。调用方必须同时判断 HTTP 状态和 `allow`，不能仅以 HTTP 200 作为放行依据。

## 7. 新权限服务固定接口

`POST http://127.0.0.1:8001/api/permission/check`

```json
{
  "trace_id": "trace_001",
  "request_id": "request_001",
  "actor_id": "user_fu",
  "action": "fetch",
  "source_service": "intent_engine",
  "target_service": "content_engine",
  "data_label": "normal",
  "data_state": "active",
  "tenant_id": "hanhe",
  "person_id": "user_fu",
  "position_id": "huazhong_sales",
  "resource_type": "data",
  "resource_id": "sales_opportunities"
}
```

正常判断包括允许和拒绝，均返回 HTTP 200；缺字段返回 422，非法业务字段返回 400，内部错误返回 500，数据库不可用返回 503。所有结果默认拒绝并留痕。

权限审计：`GET http://127.0.0.1:8001/api/permission/audits?trace_id=trace_001`。

全平台 L1/L2/L4 模块接入前读取 `GET http://127.0.0.1:8001/api/integrations/capabilities`；完整模块对照在联调包的 `permission-gateway/docs/platform-integration.md`。`POST /api/integrations/events` 为异步事件地址预留，v1 固定返回 HTTP 501，不得用它写入权限事实。

## 8. 模式切换

| `PERMISSION_MODE` | 权限结果来源 | 故障行为 |
|---|---|---|
| `local` | 网关本地 SQLite/Casbin/组织 Store | 保持当前行为 |
| `shadow` | 返回本地结果，同时调用权限服务比对 | 权限服务差异仅记录日志；组织和权限聚合写入权限服务 |
| `remote` | 独立权限服务 | 超时或错误返回 503 且拒绝，不回退本地 |

## 9. 联调追踪

每个业务请求应生成唯一 `request_id`，每条跨服务调用链应共用 `trace_id`。同一值必须贯穿业务日志、网关校验和权限决策审计。
