# 规则计算引擎项目现状交接说明

更新日期：2026-07-20

## 1. 交付范围

本说明仅对应当前 `05_规则计算引擎` 目录。目录内已包含后端代码、测试、运行脚本、路径三本地模拟服务和交付说明；核心验证不依赖其他目录。

本引擎未来需要与平台服务联调，但正式平台服务、历史会议资料和其他引擎代码均不包含在本交付包内。

## 2. 项目定位

规则计算引擎属于 L2 业务引擎层，是企业确定性计算能力的组织、执行和治理模块。它负责接收计算任务、提出必要查询、匹配已发布能力、锁定规则/参数/能力版本、组织获授权输入、调用执行能力、校验结果、判断状态并形成追溯记录。

真正的金额、比例、区间、公式和查表计算由固定 Python、OpenL、SQL、Java、固定公式执行器或既有系统完成。本引擎不让大模型完成数值计算，也不把某个演示场景写死在协调器中。

## 3. 已确认边界

### 本引擎负责

- 任务前置评估、计算路径选择、能力匹配和版本锁定。
- 规则、参数、能力和数据引用的一致性校验。
- 确定性执行、现有系统结果校验、候选实现的沙箱试算与结果校验。
- 自动通过、待真人处理、阻断三类状态和原因码。
- 规则版本的草稿、测试、审核、发布、停用等原型治理能力。
- 本引擎自有规则结构、输入输出合同和校验要求的定义。

### 本引擎不负责

- 不直接识别自然语言意图、解析 Word/Excel/PDF，或决定流程编排。
- 不自建账号、岗位、权限、安全、审批、通知或企业数据体系。
- 不修改外部系统已有的业务逻辑或代码。
- 不直接创建、登记、打标签或发布正式 Skill；候选 Skill 的资产创建和登记由平台资产能力完成。
- 大模型只辅助理解任务、提出候选能力/路径和缺失条件；正式规则参数、业务数值、权限、审核条件和放行结论必须来自已发布规则、获授权数据和真人责任机制。

## 4. 三条计算路径

### 4.1 确定性规则计算路径

适用于已登记、已测试、已发布的固定 Python、OpenL、SQL、Java、公式执行器等能力。

链路：匹配能力 -> 锁定能力/规则/参数版本 -> 取得获授权数据 -> 固定程序执行 -> 校验 -> 定状态 -> 留痕返回。

同一能力版本、规则版本、参数版本和输入数据应得到一致结果。历史生效版本不可原地覆盖；变更必须形成新版本。

### 4.2 现有系统结果路径

当某项计算口径由既有系统权威维护时，本引擎只校验返回结果的来源、期间、版本、完整性和结果合同，不重写或重算对方逻辑。当前项目提供可替换的本地适配器，用于验证该合同。

### 4.3 候选 Skill 与执行沙箱路径

当没有正式能力覆盖、且任务具有明确计算目标、输入输出约束和获授权数据时，可进入候选 Skill 路径：

1. 本引擎返回 `waiting_human / authorize_ai_generation`；
2. 业务发起人同意后，`rule.candidate_skill_apply` 接收真人授权；
3. 本引擎返回 `candidate_skill_creation_request`，包含任务、数据引用、临时分析规格、校验要求和 `candidate_request_id`；候选实现回传时必须携带相同编号，防止不同人员、任务或代码串用；
4. 平台资产能力后续创建候选 Skill 与候选 Python 实现；
5. 候选实现引用返回后，`rule.candidate_trial` 恢复原任务；
6. 本引擎调用 L1.14 Agent 执行沙箱适配器进行受控试算、自动校验并返回 `waiting_human / review_sandbox_result`。

当前已实现候选 Skill 申请、候选实现恢复试算和本地沙箱模拟的合同闭环；尚未与真实数字资产引擎、L1.3 进化机制或生产级 L1.14 Agent 执行沙箱联调。

沙箱结果不自动写回、不自动成为正式能力。只读低风险结果可由发起人确认采用；关键数字、正式写回或正式能力沉淀仍需指定岗位确认、测试、审核和发布。

## 5. 结果状态与真人处理

对外运行状态：

- `automatic_pass`：规则、数据、权限和校验满足，且结果处理规则允许自动完成。
- `waiting_human`：需要真人确认、异常处置、补数重算、AI 生成授权或沙箱结果复核。
- `blocked`：身份、权限、安全、规则、参数、版本、数据或校验不满足，不能输出正常业务结果。

当前处理类型：

- `confirm_effective`：真人确认后结果可按业务规则生效。
- `exception_disposal`：真人终止当前结果。
- `supplement_and_recalculate`：补齐或修正条件后重新计算。
- `authorize_ai_generation`：授权生成候选实现，不代表认可后续试算结果。
- `review_sandbox_result`：复核候选实现的试算结果。

## 6. 当前后端实现

代码位于 `rule_calc_engine_core/`，已经实现：

- 固定 Python 坏账准备能力、订单价格/数量区间审核，以及配置驱动的明文规则执行样例。
- 精确/区间查表、加减乘除、条件比较、计数、求和等受限操作；不使用 `eval` 或任意字符串代码。
- 能力目录、规则版本、执行记录、人工作业和幂等记录的 L1.7 风格端口；SQLite 仅作开发适配器。
- 基于能力登记的权限动作、版本生效时点判断、输入合同校验、公式反推、边界校验、合计校验和执行证据摘要。
- L1.5 大模型调度的本地合同适配器：可辅助任务理解和候选路径判断，但候选结果必须由已发布能力目录和能力类型确定性复核。
- 现有系统调用的内部合同与本地模拟适配器。
- L1.8 账号网关、L1.1 权限管理、L1.9 安全合规、L1.7 数据、L1.10 设备与系统接口、L1.14 Agent 执行沙箱的本地适配器。
- 平台标准入口 `POST /api/v1/instructions` 和能力发现接口 `GET /api/v1/capabilities`。

`rule.evaluate` 已实现两阶段机制：

1. 未提供业务数据引用时，进行身份、申请权限、安全和模型辅助初判，返回 `precondition_query_required`，列出正式计算依据、已发布计算能力、获授权业务数据三类受限查询需求；此阶段不读取业务数据、不执行计算。
2. 补齐 `context.data_refs` 后，再执行规则/能力锁定与三条路径之一。多个引用时必须唯一标注 `purpose=calculation_input`；`rule_parameter` 引用只能作为版本一致性证据，不能覆盖正式参数。

公开平台动作：

- `rule.evaluate`
- `rule.candidate_skill_apply`
- `rule.candidate_trial`

旧的 `rule.calculate` 仅保留为本地兼容入口，不作为对外能力登记。

## 8. 当前限制与后续联调项

### 8.1 流程执行引擎自动续办

当前流程执行引擎已具备固定子任务派发、回调记录和暂停/恢复骨架，但尚未实现规则计算引擎两阶段任务的自动续办。首轮联调应按固定步骤人工完成：先派发一次 `rule.evaluate` 取得 `precondition_query_required`，再补齐引用后以新的 `message_id` 和 `idempotency_key` 派发第二次 `rule.evaluate`。

后续如需自动化，流程执行引擎应在收到 `precondition_query_required` 后：

1. 按 `requirements` 创建正式计算依据、已发布计算能力和获授权业务数据的查询子任务；
2. 等待查询回执并汇集 `rule_ref`、`parameter_ref`、`data_ref` 和候选能力查询结果；
3. 校验引用完整后，沿用原 `trace_id`、`task_id`、`subtask_id`，使用新的 `message_id` 和新的 `idempotency_key` 自动回派 `rule.evaluate`；
4. 将下游 `waiting_human` 转为真人待办，并在处理完成后续办；查询失败、引用缺失或超时时停止回派并返回明确原因。

规则计算引擎已支持“首次前置评估 -> 补齐引用后的第二次 `rule.evaluate`”以及候选 Skill/沙箱试算续办合同；自动化能力主要待流程执行引擎、L1.7 数据和数字资产引擎补齐真实查询与编排接口。

- L1.5 大模型调度当前为本地合同模拟，真实模型调用尚未验证。
- L1.7 数据、L1.8 账号网关、L1.1 权限管理、L1.9 安全合规、L1.10 设备与系统接口和 L1.14 Agent 执行沙箱均未替换为正式平台实现。
- 候选 Skill 创建申请和候选实现恢复试算已完成；真实资产创建、标签登记、候选代码生成和正式发布仍待平台资产能力联调。
- 本地 SQLite 不应作为正式生产存储；正式存储与查询须由平台数据能力承接。
- 首次前置评估已有追踪编号和幂等记录，但尚未形成独立长期评估记录；其正式存储口径待平台数据合同明确。
- 规则/计算依据、参数、数据、候选实现等正式引用字段仍需与平台公共合同对齐。
