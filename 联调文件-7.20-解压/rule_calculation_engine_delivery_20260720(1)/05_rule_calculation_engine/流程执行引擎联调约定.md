# 规则计算引擎与流程执行引擎联调约定

更新日期：2026-07-20

## 1. 联调目的与边界

流程执行引擎负责接收并组织整件业务任务、派发规则计算子任务、组织必要查询和真人处理、汇总后续结果；规则计算引擎只完成其被派发的规则计算评估、确定性执行或候选实现试算。

规则计算引擎不直接查询 L1.7 数据模块、不直接查询数字资产引擎，也不自行派发其他 L2 引擎任务。需要规则、参数、数据或候选 Skill 信息时，规则计算引擎以受限查询需求或候选 Skill 创建申请回传给流程执行引擎，由流程执行引擎继续组织。

当前联调入口：

- 服务编码：`l2.rule_calculation`
- 入口：`POST /api/v1/instructions`
- 调用方：`l2.workflow_execution` 或兼容别名 `l2.flow_execution`
- 公开动作：`rule.evaluate`、`rule.candidate_skill_apply`、`rule.candidate_trial`

## 2. 两阶段 `rule.evaluate`

### 第一阶段：前置评估

流程执行引擎派发 `rule.evaluate`，但尚未提供 `context.data_refs`。规则计算引擎完成身份、申请权限、安全和模型辅助初判，不读取业务数据、不执行数值计算。

返回的顶层协议为：

```text
reply_type = success
result.result_type = data
result.data.state = precondition_query_required
```

`result.data.requirements` 固定列出以下受限查询类别：

1. `formal_calculation_basis`：正式制度、规则或参数依据；
2. `published_calculation_capability`：是否存在已发布且可调用的固定计算能力；
3. `authorized_business_data`：本次计算所需的获授权业务数据。

`precondition_query_required` 是规则计算引擎的业务状态，不是平台新增的顶层 `reply_type`。

### 第二阶段：补齐引用后执行

流程执行引擎组织相关查询后，再次派发同一 `rule.evaluate`，在 `context.data_refs` 中提供：

- 唯一的 `purpose=calculation_input` 数据引用；
- 可选且唯一的 `purpose=rule_parameter` 版本一致性引用；
- 其他正式引用可随报文保留为追溯证据。

第二阶段必须沿用第一阶段的 `trace_id`、`task_id` 和 `subtask_id`，但必须使用新的 `message_id` 和新的 `idempotency_key`。原因是本引擎按“调用方 + 动作 + 幂等键 + 请求摘要”防重复；补齐引用后的报文内容已经变化，复用第一阶段幂等键会返回 `idempotency_conflict`。

当前结果映射如下：

| 引擎业务状态 | 顶层回复 | 流程执行引擎处理 |
| --- | --- | --- |
| `automatic_pass` | `success / data` | 汇总正常结果。 |
| `waiting_human` | `accepted / task_receipt` | 按 `handling_type` 组织真人待办或后续处理。 |
| `blocked` | `failed` | 按稳定 `error.code` 终止、补数重试或转人工。 |

## 3. 候选 Skill 与沙箱路径

当第二阶段确认没有正式可调用能力时，规则计算引擎返回 `waiting_human / authorize_ai_generation`，不自行创建 Skill。

1. 真人同意后，流程执行引擎派发 `rule.candidate_skill_apply`；
2. 本引擎返回 `candidate_skill_creation_request`，其中包含任务、正式数据引用、输入输出约束、校验要求和 `candidate_request_id`；数字资产引擎返回候选实现时必须原样带回该编号，否则本引擎拒绝进入沙箱；
3. 流程执行引擎组织数字资产引擎、L1.3 进化机制等后续建设；
4. 候选实现引用返回后，流程执行引擎派发 `rule.candidate_trial`；
5. 本引擎在 L1.14 Agent 执行沙箱适配器中试算、校验，并返回 `waiting_human / review_sandbox_result`。

候选试算结果不得自动写回，也不得自动成为正式能力。只读低风险结果可由发起人确认采用；关键数字、正式写回或正式能力沉淀仍须按后续平台岗位与发布机制处理。

## 4. 当前联调限制

流程执行引擎的架构协议已定义派发、回调、暂停和续办，但当前演示代码尚未实现“识别 `precondition_query_required` 后动态派发规则/数据/Skill 查询，再自动回派原计算任务”的完整编排。

因此第一轮联调可按人工或固定测试编排完成两次 `rule.evaluate` 调用：先取得前置查询需求，再带引用回派第二阶段。动态编排规则、最终引用字段和真实数据/数字资产/沙箱接口，待平台协议进一步冻结后再接入。
