一、我提供给其他模块的能力：
1. 独立环境隔离（核心功能一）
   - 程序运行：能力编号 CAP.SANDBOX.CODE.RUN，动作 sandbox.code.run。L2 提交 AI 临时生成的 Python 程序和输入，本模块按任务动态创建独立 Docker 容器运行；任务间不共享容器、文件目录或网络。
   - 网页打开：能力编号 CAP.SANDBOX.BROWSER.RUN，动作 sandbox.browser.run。L2 提交已批准白名单 URL，本模块按任务动态创建内部网络、egress-proxy、Chromium 容器和结果目录。
   - 隔离证据：代码任务默认 network=none；浏览器任务只能进入本次内部网络；宿主机未挂载文件不可读取；容器结束后删除容器、代理和内部网络。

2. 资源上限（核心功能二）
   - 每次代码/浏览器任务均可指定 timeout_seconds、memory_mb、cpu_cores；后端限定时长 1-300 秒、内存 64-4096MB、CPU 0.1-8 核。
   - Docker 实际执行参数包含 CPU、内存、进程数上限和超时清理；跑飞程序到时会被停止并清理，不会无限占用服务器。
   - 返回证据包含实际 limits、duration_ms、cost/usage 字段和生命周期日志。

3. 越权防护（核心功能三）
   - 程序容器固定默认断网、只读根文件系统、移除 Linux capabilities、禁止提权、限制进程数；调用方不能传 Docker 命令或改变这些安全参数。
   - 浏览器容器不能直连外网，必须通过 egress-proxy；非白名单 URL 在提交时拒绝，浏览器运行过程中的非白名单连接由代理返回 403。
   - 任务执行前解析真人、公司范围和场景权限；权限不足时 Docker 不启动，资源成本为 0。
   - 当前边界：Docker 为容器隔离，不等同于 Cube/KVM/microVM；正式行为准入、真人权限和安全策略仍需接 1.4、1.8、1.9。

4. 向外连接管控与留痕（核心功能四）
   - 代码任务默认无网络，出站请求数为 0。
   - 浏览器任务动态启动专用 egress-proxy，只允许安全合规登记的域名；审计记录访问时间、方法、目标 host、URL、允许/拒绝、HTTP 状态和耗时。
   - 已真实验证：允许的受控页面返回 200；Chromium 对 Google 等非白名单后台连接被代理记录并返回 403；直连绕过失败。
   - 外发正文审计：代理已支持 POST/PUT/PATCH，记录正文长度、SHA256、Content-Type、目标、允许/拒绝和状态；不记录原文，避免把敏感正文复制进审计日志。敏感字段脱敏结论需由 1.9 正式安全合规服务接入后提供。

5. 固定生命周期与结果/快照（核心功能闭环）
   - 生命周期：受理 -> 身份/权限预检 -> 秒级创建独立环境 -> 隔离执行 -> 取回结果与文件 -> 销毁容器/网络/代理 -> 审计和成本记录。
   - 结果回传：返回 task_id、业务结果、结果文件、运行时、资源限制、日志和审计证据给发起 L2 引擎。
   - 快照：retain_snapshot=true 时保存不可变证据快照，包含运行时、日志、结果文件 SHA256；不保留可继续运行的容器。

6. 已登记场景模板执行能力（测试与验证能力）
   - 能力编号：CAP.SANDBOX.TASK.RUN，动作 sandbox.template.run。
   - 说明：运行 20 个汉和岗位场景模板，用于验证上述四项核心功能；模板不是完整业务系统，真实 ERP/OA/CRM 数据需要通过 1.10 接入。

二、我提供的接口：
接口1：公司标准任务提交接口（正式联调入口）
- 路径：http://10.60.66.97:8765/api/v1/layer-interface/messages
- 方法：POST
- 请求头：Authorization: Bearer <platform-token>；Content-Type: application/json
- 输入：必须使用公司 v0.3 标准消息信封，包含 protocol_version、message_id、trace_id、request_id、parent_message_id、source、target、channel、route_type、action、capability_id、capability_dictionary_version、registry_version、actor、context、idempotency_key、deadline_at、payload。
- 来源约束：source.layer 必须为 L2；当前登记来源包括 l2.workflow_execution、l2.rule_computation、l2.external_system_connector。
- 目标约束：target.layer=L1，target.service_code=l1.execution_sandbox；route_type=task.dispatch。
- payload 输入类型：
  1) CAP.SANDBOX.CODE.RUN：code、language=python、input、limits、可选 retain_snapshot；
  2) CAP.SANDBOX.BROWSER.RUN：url、input、limits、可选 retain_snapshot；
  3) CAP.SANDBOX.TASK.RUN：scenario_id、agent、input、limits。
- 输出：HTTP 202 时返回 reply_type=accepted、request_id、trace_id、parent_message_id、flow.callback 上下文和查询路径；短任务也可能直接返回 success 或 failed。
- 成功结果：reply_type=success；data 中返回真实沙箱 task_id、业务结果、结果文件和耗时；evidence 中返回 executor、Docker runtime、limits、logs、platform_checks、审计及快照信息。
- 错误情况：invalid_platform_token、layer_route_not_allowed、source_service_not_registered、target_service_mismatch、capability_not_registered、capability_action_mismatch、invalid_deadline、trace_id_conflict、permission_denied、url_not_allowlisted、invalid_limit、failed、timeout。
- 幂等规则：同一 idempotency_key 重试不得重复创建任务；不同请求复用同一幂等键返回冲突。

接口2：公司标准任务查询接口
- 路径：http://10.60.66.97:8765/api/v1/layer-interface/messages/{request_id}
- 方法：GET
- 请求头：Authorization、X-Caller-Layer、X-Engine-Id、X-Company-Id、X-Trace-Id。
- 输入：受理响应返回的 request_id；查询时必须使用同一调用引擎、公司范围和 trace_id。
- 输出：处理中返回 accepted/running；终态返回 success/failed；success 中带 data 和 evidence，failed 中带稳定 error code 和 retryable。
- 错误情况：request_not_found、request_owner_mismatch、tenant_scope_mismatch、invalid_platform_token。

接口3：能力目录接口
- 路径：http://10.60.66.97:8765/api/v1/layer-interface/service-catalog
- 方法：GET
- 输入：无业务输入。
- 输出：协议版本、基础模块层标识、三项 capability_id、action、允许的 L2 来源、输入约束、当前 Docker 执行器和场景目录。
- 错误情况：服务未启动时无法连接；正常情况下返回 HTTP 200。

接口4：兼容接口（不作为新平台正式入口）
- 路径：/api/v1/layer-interface/requests、/api/tasks、/api/e2b/*
- 方法：POST/GET
- 输入输出：保留原有模板任务、旧演示和 E2B-like create/run/query/destroy 结构。
- 说明：这些接口用于既有网站、独立验收和兼容测试；新平台联调必须使用接口1和接口2。
